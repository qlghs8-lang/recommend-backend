2026-11-24 추가 기능: **TOPIC 주제·소재 조건**을 배경/계절과 구분했다. `흑백요리사 같이 조리나 요리 관련된 영화`처럼 예시 뒤에 명시한 소재는 그 소재로 검색하며 예시 작품의 미확인 유사성을 주장하지 않는다. SQL/도구/최종 검사에 리터럴 단어 시작 경계를 적용해 조리/모조리 오탐을 차단하고,일반 주제 추천에 연결된 제목/줄거리 원문 근거를 요구한다. 빈 결과는 해당 주제의 카탈로그 근거 부족을 안내한다. 실제 모델 새18회 평가는 미실행이다. [구현·실패재현·실제 데이터 한계](AI_TOPIC_RECOMMENDATION_2026-11-24.md). 아래 초기 기록 이후 시간 조건의 모델/브라우저 수용도 진행됐으므로 [이전 묶음 최종 인계](AI_QUALITY_CLOSURE_2026-11-24.md)를 함께 읽는다.

겨울 전용 `WinterCriteria`를 제거하고 **기존 의도 분류 호출에서 조건 추출 → 서버 검색 → 같은 조건으로 도구·최종 재검증**하는 구조로 교체했다. 다양한 조건과 후속 변경을 처리하는 Phase 6 개선이며 Phase 7은 시작하지 않는다.

## 지원 범위

| 종류 | 예시 | 처리 |
| --- | --- | --- |
| 유형·장르 | 영화, 애니메이션, 코미디 또는 로맨스, 공포 제외 | 유형/장르 토큰 필터. 포함 ALL/ANY와 제외 구분, 장르 미등록은 제외 조건에서 탈락 |
| 공개 연도 | 2000년 이후, 2010~2020년 | 등록 공개일의 최소/최대 연도, 날짜 미등록 제외 |
| 영화 길이 | 한 시간 반 이하, 두 시간 미만 | 각각 <=90 / <=119분. 유효한 등록값만 사용 |
| 회당 길이 | 한 회가 20분 이하 | TV 대표 회당 값. 영화 전체/시리즈 전체/모든 회차 길이와 구분 |
| 배경·계절 SETTING | 겨울, 여름 바다, 우주 배경 | 동적 검색어 그룹. 그룹 내 OR/그룹 간 AND, 제목·보이는 줄거리 단서 필요 |
| 주제·소재 TOPIC | 요리, 셰프의 이야기, 우주 탐험 | 실제 제목/보이는 줄거리의 단어 시작 검색. 유형·시간·참조 유지, 주제 단서와 연결된 원문 인용 필요 |
| 분위기·감상 상황 | 기분 전환, 잔잔함, 퇴근 후 가볍게 | 관련 주제어로 순위 조정 후 공개 근거에 기반한 모델 해석. 감정 변화 보장 아님 |
| 후속 변경·제외 | 로맨스는 빼고 다시, 그중 더 짧은 것, 방금 추천한 작품 말고 | 유지/변경할 조건을 추출하고 서버의 공개 참조 ID로 범위/제외 집합 적용 |
| 확인 불가 조건 | 잔인한 장면이 전혀 없음, 특정 연령에 안전, 배우/감독/국가/언어/등급/완결 여부/시리즈 전체 시간 | 조건을 버리지 않고 확인 불가 안내. 별도 메타데이터 필요 |

장르 제외는 특정 장면의 부재나 연령 적합성을 의미하지 않는다. 줄거리에 단어가 없다는 이유로 배경/장면 부재를 보장하지 않는다. 실시간 서비스/가격/순위·변경·타인 기록에 대한 기존 미지원/거절 정책도 유지한다.

## 계약과 한계

분류 JSON은 `requests`, `comparison`, `constraints`다. 조건 최대 8개, 항목은 `kind/value/source/terms`만 받는다. source는 현재 요청 또는 이어받는 최근 **사용자** 메시지의 정확한 부분 문자열(<=100 UTF-16 단위)이어야 한다. assistant 문장과 모델 기억은 출처로 쓰지 않는다. 연도/분은 범위가 검증된 정수 문자열, 장르·유형·순서·참조는 허용 목록이다. 경로별 media와 종류별 value/terms 조합을 strict JSON Schema anyOf와 서버 양쪽에서 검증한다. SQL·사용자 ID는 받지 않는다. 기존 61-case corpus의 두 필드 파싱만 내부 호환으로 남기며 제공자의 constraints 누락은 거절한다.

충돌·미지원 보장은 복합 요청의 다른 분기나 개인 기록 조회 전에 안내한다. 배경은 실제 공개 단서가 필요하고 분위기/상황은 순위와 해석에 쓴다. 검색 후보 최대 12개, 공개 줄거리 최대 400자다. 추가 검색어는 원래 사실 조건 안에서만 후보를 좁힌다. 생성 후 Content를 다시 읽어 모든 사실 조건과 인용을 검증한다. 최초 추천은 ID마다 정확한 인용 1개(<=40 단위)와 해석 <=100단위(70 이하 권장)가 필요하다. 서버가 작품별 제목/장르/줄거리 원문 조각을 선택지로 만들고 ID·필드·인용 조합을 스키마에서 묶어, 다른 작품 인용이나 원문 바꿔쓰기를 생성 단계부터 제한한다. Unicode surrogate를 나누지 않으며 작품당 최대 13개 선택지다. 적합 후보가 없으면 빈 선택을 한다. 원문 존재와 수치는 검증하지만 해석의 모든 의미·자연스러움·만족도를 보장하지는 않는다.

`ONLY_LAST`는 바로 전 assistant의 서버 공개 참조만 사용하고 비공개 목록이면 과거 공개 목록으로 대신하지 않는다. `EXCLUDE_RECENT`는 제한된 문맥의 공개 참조만 제외한다. 이미 적용한 공개 포함/제외 ID 범위도 선택 모델에 제공하되 비공개 목록/사용자 ID는 포함하지 않는다. “더 짧은”은 유효한 등록 길이 중 최소값으로 후보를 고정해 도구에도 적용하고 생성 중 길이 변경은 실패한다. 최근 최대 6턴/12개 메시지와 텍스트 예산 밖의 초기 조건은 복원할 수 없다. 별도 영구 조건 프로필은 없다. 의미 추출의 누락/오분류 가능성도 남아 있다.

서버 개인화 점수와 반응 작품 제외는 유지하며 비공개 취향을 모델에 새로 전송하지 않는다. 개인화의 분위기는 공개 주제어 순위에 반영되며 추가 모델 해석 호출은 없다. 반응 조회 턴의 자유 해석 저장 억제도 유지한다. 네트워크는 DB 트랜잭션 밖이며 실패 시 부분 턴은 저장하지 않는다.

별도 조건 추출 호출은 없다. 분류 1회(최대 512 출력) + 기존 일반 추천 루프(최대 3도구/4제공자 요청), 기본 20초/총 출력 800토큰, 재시도 0이다. 남은 출력에 따라 추천 수를 1~2편으로 낮추도록 지시한다. 스키마/문맥 증가로 입력 비용·시간은 늘 수 있다. [OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes)도 구조화 출력의 의미 오류 가능성을 설명한다.

## 데이터와 실행

`Content`와 공개 후보 DTO에 nullable `runtimeMinutes`, `episodeRuntimeMinutes`를 추가했다. 기존 API 필드는 유지한다. 현재 개발 설정의 Hibernate ddl-auto=update는 재시작 시 추가 컬럼을 생성할 수 있다. 수동 관리 환경은 [추가 컬럼 SQL](sql/phase6-recommendation-runtime.sql)을 적용하되 이미 있는 컬럼을 다시 추가하지 않는다. 실제 MySQL 변경은 자동 테스트에서 실행하지 않았다.

**기존 작품의 러닝타임 값은 자동으로 생기지 않는다.** 기존 TMDB 수집기는 길이를 수집하지 않았고 이번에 실제 작품 값을 추정하거나 대량 갱신하지 않았다. 검증한 공개 공급자/관리 데이터로 보강해야 실제 시간 조건 검색 결과가 생긴다. NULL/0/음수/1440 초과는 사용하지 않는다. 데이터 부족은 답변에 안내한다. 대표 회당 길이를 전체 시리즈나 모든 회차 길이로 확대 해석하지 않는다. 키는 채팅·소스·보고서에 넣지 않는다.

Eclipse 동기화 후 F5 → 백엔드 중지 → 재실행하고 새 대화에서 확인한다.

1. `기분 전환할 영화 추천. 공포는 빼고` → 적용 조건/공개 근거/작품별 해석.
2. `여름 바다가 배경인 영화 추천` → 계절 전용 분기 없이 실제 배경 단서 검색.
3. 길이 데이터가 있는 환경에서 `두 시간 이내 영화 추천` → `그중 90분 이하로`, `로맨스는 빼고 다시`.
4. `방금 추천한 작품 말고 다른 작품` → 최근 공개 추천 제외.
5. `잔인한 장면이 전혀 없는 작품` → 확인 불가 안내.

현재 평가·동기화 내역은 AI_PROGRESS.md를 참고한다. 기존 57/61 분류, 이전 9/9 이유 후속·3/3 겨울 측정은 당시 구현의 기록이며 최신 전체 품질 점수로 합산하지 않는다.


TOPIC은 기존 총8개 조건에 포함되며 source는 현재/이어받은 사용자 원문,terms는1~4개다. SQL은 제목·줄거리앞400자에 REGEXP_LIKE를 적용하고,최종 검증과 인용 선택은 같은 이스케이프 패턴을 쓴다. 문자/숫자/밑줄 뒤의 중간 일치를 제외하며 한국어 조사는 허용한다. 붙여 쓴 복합어를 놓칠 수 있고 중심 소재임을 완전히 증명하지는 않는다. 최초 일반 주제 추천의 스키마는 장르를 제외한 TITLE/OVERVIEW 주제 단서40자 이하/필드당최대4개를 제시한다(기존 비주제 추천의최대13개 정책유지). 여러 주제는 모두 필터를 통과하고 최소하나의주제와연결된인용을요구한다. 개인화의로컬선정·기존이유후속의공개근거계약은유지한다. 이번DB쓰기/작품추가/메타데이터수집0으로,실제조리소재데이터의보강은다음별도범위다.
