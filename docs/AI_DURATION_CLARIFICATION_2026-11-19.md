# 모호한 시리즈 시간 단위 확인 — 2026-11-19

“짧게 볼 만한 시리즈 있을까?”에 제목·ID를 요구하던 문제를 개선했다. 이번 기능은 짧은 **회당 길이인지 전체 시청 시간인지 확인**하는 범위다. 제목 경계·연출 우열·TMDB/DB 확장·Phase7은 별도 작업이다.

## 동작

분류기는 기존 CLARIFY 작업에 선택적으로 제한된 사유 `TV_DURATION_UNIT`과 최신 사용자 문장의 정확한 부분 문자열 `source`를 보낼 수 있다. 일반 CLARIFY의 기존 형식과 동작은 유지한다.

```json
{"composition":{"requests":[{"route":"CLARIFY","reason":"TV_DURATION_UNIT","source":"짧게 볼 만한"}],"comparison":false,"splitAfter":null},"constraints":[]}
```

서버는 단일 CLARIFY인지, 허용된 사유인지, source가 앞뒤 공백 없는1~100 UTF-16 단위인지, **최신 사용자 원문에 실제로 있는지** 확인한다. 이전 사용자/assistant 문장만의 근거는 거절한다. 다른 route·복합 요청·추가 필드·임의 사유·잘못된 타입은 허용하지 않는다. 구조화 파싱 뒤 라우터에서도 원문 근거를 다시 확인한다. 이는 부분 문자열 증거 검증이며 시간 표현의 모든 의미를 판정하는 규칙은 아니다. 의미 선택은 여전히 모델의 책임이다.

검증을 통과하면 서버가 다음 고정 문구를 출력한다. 모델이 작성한 확인 문구나 source를 출력하지 않고 추가 자유 생성 호출도 하지 않는다.

> 회당 길이가 짧은 시리즈를 찾으시나요, 전체 시청 시간이 짧은 시리즈를 찾으시나요? 카탈로그에서는 대표 회당 길이를 확인할 수 있지만, 전체 시청 시간은 확인할 수 없어요.

- “회당 길이가 짧은 걸로” → 기존 TV 조건·SHORTER_EPISODE 검색으로 이어갈 수 있다. 대표 회당 길이가 등록된 후보 중 최단값을 사용하며 숫자 제한을 추측하지 않는다.
- 명시적인 “한 회20분 이하” → 기존 EPISODE_MINUTES_MAX 조건을 사용한다.
- “전체 시청 시간3시간 이하” → 기존 UNVERIFIABLE 안내를 유지한다. 대표 회당 값을 전체 시간이나 모든 회차의 보장으로 바꾸지 않는다.
- 일반 시리즈 추천·제목/참조 확인·확인 불가 조건·타인 기록/변경 거절은 기존 경로를 유지한다.

내부 ChatPlan에 선택적 clarification 메타데이터를 추가했다. 기존 생성자와 원본2/3필드 계획 재생을 유지하고 새 내부4필드 계획도 strict하게 읽는다. 공개 채팅 API·DB·저장 스키마는 바꾸지 않았다. 사유 자체는 DB에 저장하지 않으며 검증된 서버 답변과 빈 공개 참조만 기존 원자적 턴 저장에 전달한다.

## 스키마와 비용

기존 root composition/constraints와 단일/비교/독립 복합 구조를 유지했다. 사유가 있는 CLARIFY는 단일 작업 스키마의 별도 anyOf 분기이며 복합 작업에는 추가하지 않는다. 모든 분기는 route를 먼저 출력하고 필요한 필드와 additionalProperties:false를 지정한다. [OpenAI Docs의 Structured Outputs 제약](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)을 확인했다.

일반1필드 CLARIFY도 유효하므로 스키마만으로 시간 사유 선택이 보장되지는 않는다. 새 정책 세트는 일반 확인을 반환한 경우 사유 누락으로 실패시킨다. 모델·호출 수·전체800/분류544 토큰·20초·재시도0은 유지한다. 지시와 스키마의 입력 길이는 늘어나므로 비용 증가 가능성은 별도 측정한다.

## 별도 평가

`duration-clarification-v1.json`: 모호한 시리즈 길이4개, 명시 회당 순서/상한2개, 전체 시간1개, 일반 시리즈 추천1개, 일반 참조/필수 제외 확인2개, 확인 질문 후 회당/전체 시간 응답2개로12개다. 실제 모델 평가 전에 질문·정답과 제품 파일을 해시로 고정했다. 원본 conversation-quality-v1과 classifier-stability-v1은 수정하지 않았다.

`DurationClarificationTest`5개는 제한된 파서/스키마,원문 근거·사유 위조 거절,서버 문구와 다른 작업 미실행,새 계획 round-trip,새 평가의 조건/사유 누락 검출을 확인한다. 기존 안정성 채점기와 달리 별도 전체시간 사례는 **UNVERIFIABLE 조건으로 검색 전 안내하는 것**을 요구한다. 기존 채점기는 변경하지 않는다.

H2 `GroundedConversationTest`에2개를 추가했다: 권한 실패 시 모델 미호출,확인 질문/빈 참조 저장,후속 회당 최단 검색(90분/미등록 제외),반응 불변,위조 사유의 부분 턴 미저장,전체 시간 확인 불가 안내. 과거 정책 감사의 기록 재생도 유지한다. 그 감사의 일반 CLARIFY 출력은 역사적 기록의 재생이며 새 모델 정책의 기대 출력은 아니다.

```powershell
# 외부 호출 없음
.\mvnw.cmd test '-Dtest=DurationClarificationTest,GroundedConversationTest,QualityPolicyAuditTest'

# CHAT_EVAL_* 별칭을 사용하는 고정 합성 분류 평가. 기본은 건너뜀.
.\mvnw.cmd test '-Dtest=DurationClarificationLiveTest' '-DchatDurationLive=true'
```

## 동기화와 다음 범위

Eclipse 대상 지침·차이·최초 해시를 확인하고 제품5개/테스트3개/합성자료1개를 먼저 동기화해 해시를 검증한 뒤 실행본 회귀를 실행했다. 문서4개를 포함한 최종13파일만 동기화한다. 기존 소스·테스트·문서는 실행본 `target/duration-clarification-sync-20261119`에 백업한다. 설정·비밀 값·관계없는 변경을 복사하지 않는다. 최종 해시와 작업본 전체 회귀는 AI_PROGRESS.md 및 `target/duration-clarification/`의 manifest/로그를 확인한다.
