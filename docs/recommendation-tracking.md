# 추천 노출·클릭 계약 (2026-11-11)

> 후속 갱신: 2026-11-11 사용자 요청으로 로컬 `localhost:3306/myproject`에는 백업·복원 사전 검증 후 필요한 스키마 변경을 적용했다. [적용 결과](database-migration-20261111.md)를 참조한다. 아래 미적용 설명은 작업 당시 기록이며 다른 환경의 적용 여부는 확인하지 않았다.

## 기록 흐름

- `GET /api/recommend/for-you/reason?size=12`는 후보와 `recommendLogId`를 만든다. `size`는 1~100이다. 생성만으로 노출을 집계하지 않는다. 기존 사유 없는 `/for-you`는 통계 ID를 발급하지 않는다.
- `POST /api/recommend/impression/{recommendLogId}`는 인증 사용자 소유 후보의 최초 노출 시각 `exposedAt`을 저장한다. DB 행 잠금으로 동일 ID의 재전송을 직렬화하고 최초 시각을 유지한다.
- 홈은 추천 12개를 요청한다. 카드/히어로 면적의 50% 이상이 뷰포트 및 스크롤 영역 안에 들어오면 노출을 전송한다. 숨긴 탭, 온보딩 및 상세 모달로 가린 화면은 관찰하지 않는다. 히어로와 첫 카드는 같은 ID를 공유해 한 노출로 센다.
- 클릭은 노출 요청 성공 후 `POST /api/recommend/click/{recommendLogId}`를 호출한다. 미노출 클릭은 400, 타인 ID는 403, 없는 ID는 404다. 통계 실패가 상세 화면 열기를 막지는 않는다.
- 노출 중복 제거 단위는 **추천 ID**다. 기존 사용자+콘텐츠 24시간 재사용은 없앴다. 새 추천 요청은 같은 콘텐츠라도 새 ID이므로 새로 보이면 별도 노출이다. 스크롤 왕복·네트워크 재전송은 기존 ID로 한 번만 센다.
- 노출은 클라이언트 가시성 보고이며 사람의 주목이나 광고 과금 증명이 아니다. IntersectionObserver 미지원 시 자동 추정하지 않고 클릭 시에만 기록한다. 실패한 노출은 다음 가시성 이벤트나 클릭에서 재시도한다. 반복 클릭은 모두 저장하며 클릭 재전송 식별자는 아직 없다.

## 통계 정의

기간은 모든 집계에서 `exposedAt >= from`인 노출 집합을 뜻한다. 해당 집합에 연결된 클릭을 집계하며, 기간 이전 노출의 최근 클릭은 제외한다. 과거 기간의 수치는 뒤늦은 클릭으로 변할 수 있다.

| 필드 | 의미 |
|---|---|
| impressions | 서로 다른 노출 ID 수 |
| clicks / uniqueClicks | 한 번 이상 클릭된 노출 ID 수 |
| totalClicks | 반복 포함 클릭 행 수 |
| ctr / ctrUnique | uniqueClicks / impressions (0~1) |
| ctrTotal | totalClicks / impressions, 노출당 클릭 횟수이며 1을 넘을 수 있음 |

대시보드와 source 통계는 같은 집계 쿼리를 사용한다. 관리자 로그의 기존 응답 필드 `createdAt`에는 호환성을 위해 **실제 노출 시각**을 전달하며 후보 생성 시각은 별도 DB 필드로 보존한다. 미노출 후보는 관리자 노출 목록에서도 제외한다.

## 스키마와 배포 전 처리

운영 DB 변경은 수행하지 않았다. 새 코드는 `recommend_logs.exposed_at` nullable timestamp 컬럼과 `idx_rl_exposed_at` 인덱스를 요구한다. MySQL 기본 물리 이름 전략 기준의 수동 검토용 SQL은 아래와 같다. 이미 개발용 `ddl-auto=update`로 생성된 경우 중복 실행하면 안 된다.

```sql
ALTER TABLE recommend_logs ADD COLUMN exposed_at DATETIME(6) NULL;
CREATE INDEX idx_rl_exposed_at ON recommend_logs (exposed_at);
```

과거 로그에는 실제 노출 증거가 없으므로 자동으로 `created_at`을 복사하지 않는다. 기존 데이터는 보존하되 새 통계에서는 제외되며, 전환 후 통계가 감소하는 것은 예상된 동작이다. 기존 통계가 필요하면 전환 전 보고서를 별도 보존한다. 백엔드·프런트를 함께 전환해야 한다. 이전 프런트는 노출 API를 호출하지 않아 새 클릭 계약과 호환되지 않는다.

후보 로그도 DB에 남으므로 운영 전 미노출 후보 보존기간과 정리 작업을 정해야 한다. 기존 운영 DB에 대한 자동 마이그레이션·백필·삭제는 이 작업에 포함하지 않았다.

## 검증 범위

서비스 테스트: 후보 생성과 노출 분리, 중복 노출, 반복 클릭, 소유권·미노출·없는 ID, size 경계.
격리 H2 JPA 테스트: 실제 JPQL 집계, 미노출/기간 이전 노출 제외, 관리자 목록/대시보드 일치, 행 잠금 조회·노출 저장, 협업 추천에서 동일 사용자의 좋아요+찜을 한 명으로 집계.
프런트 테스트: 가시성 임계값, 같은 ID 공유, 숨긴 탭/모달, 실패 재시도, 관찰 API 미지원.
실제 MySQL 잠금 경합·마이그레이션 및 브라우저 양 서버 E2E는 미검증이다.
