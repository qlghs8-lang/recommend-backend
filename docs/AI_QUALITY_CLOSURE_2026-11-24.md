## 서버·실행 환경에서 확인한 것

- 서버가 허용 작업·원문 범위·신뢰할 수 있는 작품 참조를 검증한다. 실제 Content와 조건·인용을 재확인하고 완성된 질문/답변만 원자적으로 저장한다.
- 개인화는 서버가 본인 반응으로 계산한다. 추천 당시 최초 요청과 로컬 근거를 서버 전용 메타데이터로 보존하고 반복 이유 질문에 연결한다. 공개 JSON/모델 문맥에 해당 비공개 메타데이터를 노출하지 않는다.
- 실제 앱 MySQL의 nullable 출처 컬럼 적용과 별도 합성 MySQL/JWT/HTTP/React의 소유권·저장·반응 변경·새로고침·실패 초안 보존을 확인했다. [배포 수용](AI_DEPLOYMENT_ACCEPTANCE_2026-11-24.md).
- OSIV에서 관리 객체 재사용 때문에 생성 중 변경을 놓치던 추천/이유/복합 상세 조회를 스냅샷·최종 재조회로 보강했다. 합성 H2 최신성12개와 격리 MySQL 실행 환경 검사를 통과했다. 최종 조회 이후 커밋까지 모든 변경을 잠금으로 막는 보장은 없다. [최신성](AI_CATALOG_FRESHNESS_2026-11-24.md).
- 실제 공개 카탈로그 기반 React 검사에서 정상12턴·의도적 최신성 실패2회, 저장24개와 복원·초안 보존·재시도 최신 답변을 확인했다. 고정 AI의 서버/UI 계약이며 실제 모델 해석 점수가 아니다. [시간 조건 브라우저 수용](AI_RUNTIME_BROWSER_ACCEPTANCE_2026-11-24.md).

## TMDB / DB 확장 현황

기존 **468개**(영화230/TV238)를 유지한다. 검증된 TMDB 매핑으로 40개를 상세 수집해 **영화20개 + TV1개**, 총21개 시간과 별도 출처를 원자적으로 적용했다. 영화20/230=8.70%, TV1/238=0.42%, 전체21/468=4.49%이며 **447개는 미등록**이다. TV19개의 빈 회당 시간 배열은 추정값으로 채우지 않았다. 등록률은 이전 적용·검증 결과이며 이번에 DB를 다시 조회하지 않았다.

시간 조건은 미등록 값을 제외하며 TV 값은 대표 회당 시간으로 표시한다. 전체 시청 시간·모든 회차 상한의 증거로 사용하지 않는다. 수집과 저장의 안전장치·출처·멱등성과 조건 추천의 모델/서버/UI 수용까지 **제한된 A단계 21개 배치**를 완료했다. 전체 A단계 데이터 보강 완료는 아니다.

감독/배우·키워드, 국가/언어·상태, 지역별 등급·OTT 등 B~D는 제안 상태다. 관계 데이터와 출처·언어·국가·갱신 시각을 검토한 뒤 각각 수집/검색/검증/답변 수용을 연결해야 한다. 해당 정보가 현재 존재하거나 질의를 지원한다고 안내하지 않는다. [확장 설계](TMDB_METADATA_FOR_AI_CHAT.md), [실제 적용](AI_RUNTIME_APPLY_2026-11-24.md).

Eclipse **F5**로 문서를 갱신하면 된다. 이번 제품 변경은 없으므로 이번 작업을 위한 앱 재시작은 필요 없다. 직전 Java 변경을 아직 실행 앱에 반영하지 않았다면 별도로 중지·재실행한다. 사용자 앱은 재시작하지 않았다.
