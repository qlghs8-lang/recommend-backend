## 공통 추천 구조에서 해결할 일

RAG는 실제 후보 자료를 모델에 제공하는 방식이다. **키워드는 후보 발견 단서**, 줄거리는 이야기의 적합성을 비교할 근거다. 키워드가 있다는 이유만으로 중심 소재·따뜻함·안전한 가족 감상·무스포일러를 보장하지 않는다. 원문 인용 존재와 해석의 타당성도 별도다.

- `catalog_pool.py`는 수집 JSON의 원제를 중복 검토에 사용하지만 현재 `Content`/`contents`에는 독립 원제·별칭을 저장하지 않는다. 기존 수집 원본이 있으면 신뢰 가능한 매핑/해시/시각부터 확인해 재사용하고, 없거나 불명확하면 아래 제한 조회로 확인한다.
- `CatalogCandidate.from`은 줄거리 **400코드포인트**를 전달한다. 이번 감사도 Python 코드포인트 기준이다. 이전 2단계 리뷰 패킷의 UTF-16 표현은 수정하지 않았고, 그 표현을 모든 제품 경로의 정확한 재현으로 간주하지 않는다.
- `RecommendationCriteria`의 TOPIC/SETTING은 제목/앞400자 필터이고 TOPIC은 원문 단어 단서도 확인한다. `CatalogRetriever`는 최대12개와 문자열/평점/조회수 순위를 사용한다. **새 키워드 테이블만 만들면 현재 필터가 자동 확장되는 구조가 아니다.** 키워드 검색·별칭 해석·근거 검증에 연결하는 제품 변경은 4단계의 별도 비교 평가로 진행한다.
- 기존 14개 탐색 묶음을 그대로 조사용으로 사용했다. 28개 제안 표본에는 13묶음의 문자 단서가 있고 요리는 없다. 이는 13소재의 적합성 수용이나 요리 작품의 의미상 부재를 뜻하지 않는다. 스포츠카·우주 전사 같은 문자 오탐도 표본에 남겨 검토해야 한다.

## 미반영 데이터 구조 제안

아래 이름은 **설계 후보**이며 실제 엔티티·테이블·API·마이그레이션을 만들지 않았다. 기존 `catalog_import_sources`의 최초 수집 시각과 `catalog_runtime_enrichments`의 검토된21개 출처는 유지한다. 신규 메타데이터의 수집과 필드별 적용 이력은 따로 보관한다.

문자열은 외부 비신뢰 자료다. 포함된 지시문을 실행하거나 시스템 프롬프트로 쓰지 않는다. 후속 구현은 정수 ID·필드 allowlist·크기·문자열 타입·중복·출처 일치부터 검증하고 SQL은 파라미터화한다. 정규화는 원문을 보존한 별도 값으로 만들며, 검토되지 않은 번역/중심성 판단은 검색 사실 필드와 섞지 않는다.

시간은 기존 null-only 정책을 재사용한다. 영화는 유효 정수1–1440분, TV는 기존 정책에 따른 단일 고유 대표 회당 값만 제안한다. 빈 배열/여러 서로 다른 값/0/null은 자동 추정하지 않고 사유를 남긴다. TV 대표값×회차 수로 전체 시리즈 길이를 만들지 않는다. 이미 검토된21개와 다른 값이 오면 자동 덮어쓰기 대신 충돌 검토다. 회차/시즌 추가 조회는 이번 파일럿 범위 밖이다.

줄거리는 한국어 원문·조회시각·기존 해시를 비교해 변경안을 별도 보관한다. 저장 길이 초과 원문은 잘라서 자동 적용하지 않는다. 짧은 줄거리 교체·영문 fallback·모델 생성 요약은 검토 없이 자동 적용하지 않는다. 앞400자 밖의 유효 근거는 저장 정보 부족과 **컨텍스트 절단**을 구분한다. 키워드/새 요약을 모델에 전달하고 원문을 검증하는 경로 역시 별도 제품 기능이다.

## 기존468개 보강과 작품 추가의 분리

**이번 권고는 기존468개 유지**다. 447개의 시간 공백·독립 키워드/별칭 공백과 검색 필터 병목을 먼저 분리할 수 있다. 모든 빈 응답을 작품 부족 탓으로 보고 인기작을 늘리면 원인과 기준값이 함께 바뀐다. 468개를 영구 상한으로 결정한 것은 아니다.

추가 트랙은 보류한다. 여러 소재에서 기존 원문/새 키워드를 검토한 뒤에도 근거를 확보하지 못하면, 신규 요청에서 제한적인 discovery 목록을 별도 파일로 조사한다. 요리 한 소재만을 필수 목록으로 고정하지 않는다. 신규 작품은 공식 영화/TV+TMDB ID·기존 매핑·제목/연도 충돌·한국어 줄거리·장르·출처를 검토하고, 적합성·중복·성인/미래작 등 기존 수집 정책을 다시 확인한다. 추가 전후 평가 카탈로그를 따로 고정한다. **이번에는 discovery 호출·추가 후보 목록·INSERT를 만들지 않았다.**

## 다음 제한 파일럿 제안 — 아직 수집하지 않음

- 최대28작품×3 GET=**84 HTTP 시도**, 동시1·초당최대1·자동 재시도0, 요청당10초·작업전체900초·응답당1MiB 상한을 제안한다. 84회를 다 끝내기 전 전체 기한에 도달할 수도 있으며 나머지는 NOT_RUN이다. append/fallback/번역/회차 조회/새 작품 탐색/LLM 호출은 포함하지 않는다.

- 다음 기능은 **이 계획용 제한 수집기와 검토용 dry-run 구현/오프라인 검증**이다. 실제 수집은 새 요청의 범위에서 수행하며, 그 요청이 도구 구현만이면 데이터 호출은 하지 않는다. 이번 계획 파일은 실행 승인 토큰이 아니다.

- 적용은 별도 기능이다. 검토된 필드만 allowlist로 적용하고, 좁은 백업·잠금 후 기준행/매핑/예상값 검사·원자적 쓰기·출처 동시 저장·멱등성·불일치 시 전체 롤백을 검증한다. 기존21개 런타임 출처·다른 필드·468개 ID를 보존한다. 수집 파일을 제품이 자동 읽지 않는다.
