# 개인화 추천의 후속 근거 수용 검사 — 2026-11-24

**보안·저장 계약 통과, 개인화 설명 품질 게이트 미달.** 제품 코드는 바꾸지 않았다. 기존 전체 분류 평가의 수정 정책61/61·원본59/61은 이전 결과 그대로이며 이번 좁은 평가로 대체하지 않는다.

## 고정 범위

`src/test/resources/chat/personalized-rationale-v1.json`에 합성 계정 두 개, 공개 영화 세 편, 각 계정의 반응 기준 시리즈 한 편씩과 질문·판정 기준을 고정했다. 실제 사용자 DB·대화·반응을 읽지 않는다. 반응 기준 작품의 합성 비공개 표식은 모델 입력에서 빠져야 한다.

실제 H2의 ConversationService → 소유권 확인/기록 준비 → ChatRouter → 추천·조회·이유 설명 → 두 메시지 저장을 사용한다. 기본 실행에서는 AiClient만 모의 처리한다. 선택 실행은 동일 경계에서 실제 분류/근거 생성을 사용하며 개인화 선정 자체는 기존 서버 SQL/장르 점수 경로다. MySQL·HTTP·브라우저 평가는 아니다.

고정 대화는 다음 네 턴이다.

1. `내 취향에 맞는 영화 추천해줘`: 본인 SF 좋아요(+3)로 SF 영화 둘을 먼저 선택한다. 다른 계정의 Comedy 좋아요는 반영하지 않는다.
2. 테스트 코드에서 본인 좋아요를 삭제한 뒤 `이 영화들을 추천한 이유는 뭐야?`: 저장된 세 작품을 공개 근거로 설명한다. 반응 변경은 합성 자료에만 수행하며 챗봇에 쓰기 기능을 추가하지 않는다.
3. `방금 이유를 설명한 첫 번째 작품은 왜 추천했어?`: 신뢰한 이전 참조의 첫 작품을 설명한다.
4. `내 취향에 맞는 영화 추천해줘`: 현재 본인 긍정 기록 부족을 안내하고 평점 순으로 다시 고른다. 과거 답변은 바꾸지 않는다.

개인화 근거 판정은 당시 서버 표시의 존재를 확인하는 좁은 검사이며 자유 문장 전체의 진실성·자연스러움 평가가 아니다. `catalogGrounded=true`도 실제 개인화 선정 이유를 이어 설명한다는 보증은 아니다.

현재 ChatRouter는 참조 assistant 바로 앞 USER를 요청으로 사용한다. CatalogRecommendations의 후속 경로는 공개 CatalogCandidate와 그 요청/현재 질문만 받는다. 최초 추천의 서버 취향 계산을 후속용 구조화 메타데이터로 저장하지 않는다. 개인 정보를 모델에 더 보내는 방식으로 해결하지 않았다.
