# 연출 우열 질문의 한계·대안 안내

범위: 특정 작품 사이의 연출·연기·작품성 우열 질문에 맞는 안내 한 가지. 공개 API·DB·프런트엔드·모델·토큰 상한은 변경하지 않는다.

## 문제와 동작

원본 질문은 “달빛 항해와 숲의 기록 중 더 뛰어난 연출의 작품은 뭐야?”다. 이전 감사에서 기록된 UNSUPPORTED는 실시간 순위 미지원 안내를, 원본 CLARIFY는 이미 주어진 제목/ID를 다시 묻는 문구를 반환했다. 두 답변 모두 우열을 발명하지 않았지만 질문에 맞는 안내가 부족했다. 과거 원본61개 결과58/61과 정답은 보존한다.

단일 CLARIFY에 QUALITATIVE_COMPARISON 사유를 추가한다. 모델이 전달하는 source는 최신 사용자 메시지에 그대로 존재하는1~100 UTF-16 문자이며 앞뒤 공백을 허용하지 않는다. 기존 strict 파서·단일 요청 규칙·서버 재검증을 사용한다. 추가 필드나 이전 턴에만 존재하는 근거는 거절한다. source를 답변으로 사용하지 않는다.

서버 고정 답변:

> 연출·연기·작품성의 우열을 판단할 검증된 평가 자료가 없어 어느 작품이 더 뛰어나다고 답할 수 없어요. 카탈로그에 저장된 장르·유형·공개일·줄거리를 나란히 비교하거나, 작품을 특정하지 않는 일반적인 연출 평가 기준을 설명할 수 있어요.

이 안내에서는 카탈로그·개인 반응 조회와 추가 생성 호출을 하지 않는다. catalogGrounded=false, 공개 작품 ID 목록은 비어 있다. 질문에 나온 작품이 카탈로그에 있다고 주장하지 않는다. 실제 저장 정보 비교는 사용자가 두 작품을 명시한 별도 요청에서 기존 정확한 상세 조회를 수행한다. 단순 “응”으로 이전 제목을 복원하는 새 상태 추적은 추가하지 않는다.

일반 연출 평가 기준은 EXPLAIN, 우열을 요구하지 않는 저장 정보 비교는 기존 두 DETAIL이다. 새 추천은 기존 RECOMMEND/PERSONALIZED다. 타인 기록 조회의 DENIED와 변경/실시간 자료의 UNSUPPORTED가 우선한다. 정보 비교와 우열 요청을 함께 받으면 가능한 부분만 몰래 실행하지 않고 한계 안내를 반환한다.

## 검증 설계

- QualitativeComparisonTest: strict 원문·사유 검증, 고정 안내·대안, 조회/추가 생성 없음, 공개 참조 없음, 잘못된 일반 CLARIFY/UNSUPPORTED/정보 비교만의 결과를 잡는 별도 정답 검사.
- GroundedConversationTest: 실제 H2 서비스에서 소유권 선검사, 안내 저장·빈 공개 참조, 위조 근거의 원자적 실패, 두 ID를 명시한 후속 비교의 저장 행·공개 참조·반응 불변 확인. 모델은 mock이다.
- qualitative-comparison-v1.json: 별도15개×3회 고정 합성 정책. 원본/영문/ID/주관 요구/이전 작품/혼합 요청, 일반 설명·정보 비교·실시간 순위·변경·권한·추천, 기존 시간단위·제목 사유, 안내 후 명시 비교를 포함한다. 정답을 실제 모델 실행 전에 고정한다.
- 실제 모델 평가는 기존 분류/라우터 계약 평가기를 사용한다. 하위 카탈로그/추천/설명 서비스가 mock이므로 SQL·사실성·저장 점수와 구분한다. 원본 corpus·채점기는 완화하지 않는다.

```powershell
.\mvnw.cmd test '-Dtest=QualitativeComparisonTest,TitleBoundaryPlanTest,DurationClarificationTest,GroundedConversationTest,QualityPolicyAuditTest'
.\mvnw.cmd test '-Dtest=QualitativeComparisonLiveTest' '-DchatQualitativeLive=true'
.\mvnw.cmd test '-Dtest=ClassifierStabilityLiveTest' '-DchatStabilityLive=true'
.\mvnw.cmd test
```

유료 opt-in은 기존 CHAT_EVAL_* 환경 별칭을 자식 셸에서만 설정하고 제거한다. 고정 합성 데이터만 사용하며 비밀·사용자 대화는 기록하지 않는다. 새 정책은 기본 전체800/분류544, 기존 안정성은2048/분류1024, 모두20초/SDK 재시도0이다.

OpenAI [구조화 출력 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)의 required/additionalProperties=false 및 키 순서 규칙을 확인했다. 기존 중첩 합성 스키마를 유지하고 allowlist 사유만 늘린다. 구조화 출력의 형태 준수가 의미적 분류 정확성을 보장하지는 않는다.

## 실행 결과와 인계

관련65개 오프라인 검사가 통과했다. Eclipse 챗봇 회귀는384개 중369통과/유료15조건부 건너뜀,실패·오류0이다.

새 정책의 실제 gpt-6-luna 평가는 **45/45 통과**했다. 전체800/분류544/20초/재시도0,각15사례3회이며45개 provider 응답 모두 completed였다. 보고 사용량 입력217983/출력5147토큰,분류 지연p95 4724ms다. 보고서는 `target/chat-quality/qualitative-comparison-20261119103934101584100.json`,SHA256 `bf5452313b5a3506cea2e8c9d757e66a5dd61e06e434ae86130741b0bdbbbc04`다. 이는 분류/라우터 계약 점수이며 실제 SQL·저장·사실성 모델 검사가 아니다.

변경하지 않은 원본 안정성21개×3회도 **63/63 통과**했다. 전체2048/분류1024/20초/재시도0,보고 사용량 입력307941/출력17088토큰,p95 6390ms다. `target/chat-quality/stability-20261119104246030556900.json`,SHA256 `72ca57c4a6427e4687a157a4c5110b603e40064a17e13c76a82636c49723b38c`다. 원본 전체61개는 다시 실행/재채점하지 않았다. 기존58/61은 이전 측정이며 전역 품질 수용 완료로 바꾸지 않는다.

이번 실제 모델 요청은 고정 합성108회,보고 사용량 합계 입력525924/출력22235토큰이다. 이는 과금 총액이 아니다. 새 정책 자료 SHA256은 `1cb1191e71bd3d394ab716f255426677605c7313eab872f383609295ad203728`이며 유료 평가 전 고정본과 일치한다. 기존9개 자료와 평가기는 유지했다.

최종 작업본 `./mvnw.cmd test`는479개 중429통과/50조건부 건너뜀,실패·오류0이다. 실행 로그는 `target/qualitative-comparison/full-offline.log`다. Eclipse `./mvnw.cmd test '-Dtest=com.example.recommend.chat.**.*Test'` 결과는384개 중369통과/유료15건너뜀이다. 제품·테스트는 이 검증 후 변경하지 않았다.

초기 제한 환경 실행은 첫 Mockito 초기화에서 진행되지 않아 해당 세션만 중단했다. 접근 가능한 환경의 첫 실행은58개 중2오류였다. 새 자료의 추천 media를 내부 정규형 ANY+MEDIA 조건으로 표현하지 않은 테스트 오류와, 서비스 테스트가 공유하는 분당60개 한도 충돌이었다. 정답 표현은 유료 실행 전에 수정했다. 테스트 한도를 Bean setter에서 바꾼 첫 시도는 설정 바인딩에 덮여 한도 오류1개가 남았다. 최종적으로 H2 테스트 속성에만600을 지정하고 운영 한도 경계를 확인하는 기존 ChatServiceTest를 함께 실행했다. 운영 한도는 바꾸지 않았다. 유료 실행 전 새 자료/제품/테스트8개 파일을 다시 고정했으며 원본9개 자료는 불변이다.

실행본 동기화 최초 명령은 스크립트의 상대 경로를 잘못 사용해 실패했다. 이어 실행된 구버전 검사는 해당 세션만 중단했고 수용 결과에 포함하지 않는다. 절대 경로로 스크립트를 실행해 백업·해시 검증을 끝낸 다음 수정된 실행본의 회귀를 통과했다. 앱은 재시작하지 않았다.

MySQL·화면 수동 수용 검사는 별도이며, 모델이 새 사유를 항상 선택한다는 보장은 없다. 감독/배우 메타데이터만 확장해도 주관적 우열의 근거가 생기지는 않는다. TMDB/DB 확장과 간헐503 조사는 별도 단계다.

실행본 소스/테스트/자료8개는 최초 지침·차이·해시를 확인하고 동기화했으며, 덮어쓴5개는 실행본 `target/qualitative-comparison-sync-20261119`에 원본 해시 그대로 백업했다. 문서4개도 최종 기록 후 동기화하고 기존3개를 같은 위치에 백업한다. 설정·비밀·관계없는 변경은 복사하지 않는다. 최종12개 일치/백업8개/기존 자료9개/유료 실행 전8개 해시는 `target/qualitative-comparison/final-manifest.json`으로 검증한다. 실행본 회귀 로그는 `target/qualitative-comparison-offline-verification.log`다.

앱은 재시작하지 않았다. Eclipse F5 후 백엔드를 중지·재실행해야 적용되며 Eclipse 자체 재시작은 필요 없다. 다음 단일 기능은 수정된 세 정책의 통합 대화 수용 평가다. 원본 v1 점수와 새 정책 점수를 분리하고 별도의 대화 시나리오를 고정해 실제 서비스 연결을 검증한다. 다른 기능은 자동 시작하지 않는다.
