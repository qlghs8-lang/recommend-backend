# D10 추천 스키마 HTTP400 원인확정 진단

2026-11-25 KST. **고정한 D10 스키마의 직접 원인은 공개 원문 인용 enum 안의 줄바꿈(U+000A)이다.** 동일 모델·엔드포인트·SDK에서 원본/최소 스키마는 거절되고, 각각 줄바꿈 두 글자만 공백으로 바꾼 대조군은 수용됐다. 제품 수정은 이번 범위에 포함하지 않았다. [첫 파일럿](AI_BASELINE_DIAGNOSTICS_2026-11-25.md)의 실패와 D11/D12 `NOT_RUN`은 보존하며, 2단계 전체 완료나 추천 품질 합격으로 해석하지 않는다.

## 고정 입력과 인과 비교

사용자가 승인한 `gpt-6-luna`와 기존 최대 $1을 유지했다. 별도 진단 실행기는 최대 4요청·추정 예약비용 $0.10·요청당 출력 128토큰·20초·SDK 재시도 0으로 제한했다. 사용자가 로컬 터미널의 숨김 입력으로 실행했다. 키는 문서/파일/명령 인자에 저장하지 않았다. 공개 스키마만 전송하고 DB·회원·비공개 대화·추천 턴 실행은 0이다.

동결 입력: `src/test/resources/chat/schema-d10-original-v1.json`. SHA-256:
`a17426126d3df3266172cf49539b0edd95e9fc87c9cd2f35a6742dbd41665f25`.

문제 위치는 `/properties/recommendations/items/anyOf/10/properties/evidence/items/anyOf/0/properties/quote/enum/0`, 공개 contentId 404 **나루토**의 인용이다. JSON 이스케이프 표기로 `동료들이 닌자가 되기 위한 모험을 떠나는 흥미진진한 작품. \n\n닌자 마을`이며, 실제 문자열에는 LF가 두 개 있다. 제품 `OpenAiClient.topicQuotes`가 공개 줄거리의 단서부터 최대 40 UTF-16 글자를 취하면서 빈 줄을 포함했다. 원문을 그대로 동적 enum에 넣는 경로가 공급자 스키마 검증에서 거절됐다.

| 순서 | 입력 | 두 LF 외 변경 | 관측 결과 | 지연 |
|---|---|---|---|---:|
| 1 | 전체 원본 | 없음 | HTTP400 `invalid_json_schema` | 1,960ms |
| 2 | 전체 LF→공백 대조군 | 없음 | 스키마 수용, completed | 3,684ms |
| 3 | quote 필드만 남긴 최소 원본 | 전체 쌍과 별도 축소 | HTTP400 `invalid_json_schema` | 87ms |
| 4 | 최소 LF→공백 대조군 | 3번 대비 없음 | 스키마 수용, completed | 3,753ms |

각 쌍은 LF 두 글자와 공백 두 글자만 다르고 문자열 길이도 같다. 오프라인 검사는 전체 스키마의 해당 값 복원 후 깊은 동등성 및 최소 쌍 동등성을 확인한다. 두 거절 응답 모두 공급자가 동일 인용 필드의 LF를 직접 지목했다. 이는 고정 조건에서의 인과 확인이며 모든 모델/스키마 오류나 과거 간헐 503의 원인을 일반화한 결과가 아니다. 수용된 두 응답도 추천 적합성 검증이 아니다.

[공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)의 지원 부분집합과 크기 제한을 참고했다. 해당 문서 자체를 LF 제한의 직접 근거로 사용하지 않는다. 고정 스키마의 로컬 집계는 속성 61개·enum 값 37개·이름/enum 문자열 1,030자·최대 컨테이너 깊이 5이며, 이번 LF 원인 판정의 근거는 위 통제 비교와 실제 공급자 검증 메시지다.
