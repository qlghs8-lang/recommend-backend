# AI 채팅 품질 평가 보고서

평가일: **2026-11-18 · 한국 시간**  
결론: **카탈로그 사실 검증과 기본 후속 참조는 개선됐지만, 실제 사용 품질 수용은 아직 어렵다. 분류 안정성·복합 요청·개인화 이유의 일관성을 먼저 개선해야 한다.**

## 1. 평가 범위와 방법

- 현재 체크아웃의 실제 `OpenAiClient`, `ChatRouter`, 검색·도구·개인화·대화 저장 서비스를 사용했다. 제품 코드나 모델 프롬프트는 수정하지 않았다.
- 현재 설정된 `gpt-6-luna`로 기존 분류 세트 61항목과 별도 대화 47턴을 실행했다. **총 108개 평가 항목이며, 같은 질문의 진단 재질문도 포함한다. 108개 서로 다른 질문이라는 뜻은 아니다.**
- 대화는 33개 격리된 대화방에서 실행했다. 이 중 여러 턴 대화에서는 실제 생성한 답변과 서버 작품 참조를 저장하고 다음 질문에서 재조회했다.
- 가상 카탈로그 15편과 가상 사용자의 좋아요·찜·싫어요만 H2에 넣었다. 실제 사용자 DB·개인 대화·브라우저·HTTP/JWT는 이 유료 평가에 사용하지 않았다. 작품·시간·연도는 테스트용 가상 값이다.
- 자동 검사는 경로, 작품 조건, 참조, 저장, 일부 금지 요청, 편수·간결성 등을 검사한다. 별도로 모든 생성 답변을 직접 읽어 유용성·일관성·자연스러움을 검토했다. **자동 통과율은 종합적인 답변 품질 점수가 아니다.**
- 일반·경계·권한 우회 사례를 함께 구성하는 방법은 [OpenAI 공식 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고했다. LLM 심판 점수는 사용하지 않았다.

## 3. 중요도별 발견 사항

P0=개인정보 노출·권한 우회 등 즉시 차단, P1=핵심 기능·신뢰성을 해치는 문제, P2=유용성·사용성 개선, P3=후속 확장으로 구분한다.

### P0 — 이번 범위에서 재현하지 못함

타인 반응 요청·관리자 주장·SQL 조회 지시는 거절됐다. 모델 오류가 난 두 서비스 턴에서 사용자/AI 메시지가 일부만 저장되지 않는 것도 확인했다. 다만 이것은 **제한된 합성 사례**의 결과다. 새로운 HTTP 인증 공격, 실제 계정 간 대화방 접근, 운영 보안 전체를 검증했다는 뜻은 아니다.

### P1-1. 정상적인 조건 변경이 완성되지 않은 분류 결과로 실패함

- **재현:** “우울해서 기분 전환할 영화…한 시간 반 이하…공포는 빼고” 추천 뒤 “그중 더 짧은 걸로 골라줘”.
- **관찰:** 직전 추천은 정상이나 후속 턴은 `AI_INVALID_RESPONSE`. 제공자 상태는 `incomplete`, 출력은 **512토큰**, 제공자 호출은 1회였다. 추천 생성 전 분류 단계에서 끝났다.
- **영향:** 사용자는 이미 이해한 조건을 짧게 수정했는데 연결이 끊긴다. 턴 전체 예산이 2,048이어도 분류 상한 512는 그대로다.
- **원인 해석의 한계:** 512토큰에서 incomplete였다는 것은 관찰 사실이다. 해당 실행에서 제공자의 세부 종료 사유는 수집하지 않아 그 이상의 원인을 확정하지 않는다.
- **개선:** 반복되는 조건·원문 복제를 줄이는 분류 표현과 분류/후속 생성 예산 배분을 함께 점검한다. 무조건 재시도를 추가하는 방식은 먼저 적용하지 않는다.
- **수용 기준:** 조건 1~8개와 짧은 후속 변경을 별도 고정 세트로 만들고, 동일 예산의 사전 지정 반복에서 오류율·토큰을 함께 검증한다.

### P1-2. 복합 요청의 원문 재출력이 깨져 전체 요청이 거절됨

- **재현:** “내 찜 목록을 보여줘. 그리고 내 취향으로 새 영화 추천해줘”. 기존 61항목과 실제 서비스 평가 모두 실패했다.
- **관찰:** 서비스 실행에서는 `LIST_BOOKMARK`와 `PERSONALIZED` 자체는 맞게 골랐다. 그러나 두 번째 작업을 `내 취향으로 새 영화 추천해줘.`로 만들어 **원문에 없던 끝 마침표를 추가**했다. 서버의 정확한 원문 검증이 이를 거절했다.
- **영향:** 지원하는 두 기능의 자연스러운 조합이 일반 오류로 끝난다.
- **개선:** 원문 전체를 모델이 다시 쓰도록 하는 부담을 줄이고 서버가 검증된 원문 범위를 복원하도록 설계를 검토한다. 연결어·구두점 사례를 확대하되, 원문 누락/변조를 그냥 허용하는 방식으로 검증을 약화하지 않는다.
- **수용 기준:** 마침표 유무, “그리고/다음으로/보여주고”, 순서 변경에도 두 작업이 보존되고 원자적으로 저장돼야 한다.

### P1-3. 개인화 추천과 후속 추천 이유가 서로 모순됨

- **재현:** “내 취향을 반영해서 새 영화 추천해줘” → “이 작품들을 나한테 추천한 이유는 뭐야?”
- **실제 첫 답변:** `좋아요·찜에서 얻은 장르 선호와 일치: drama … 장르 점수 5`.
- **실제 후속 답변:** `취향 정보가 없어 맞춤 여부는 불확실해요`, `맞춤 추천인지는 알기 어려워요`.
- **영향:** 실제로 개인화했는데 곧바로 그 사실을 설명하지 못한다. 작품 ID가 맞아 자동 검사는 통과했지만 수동 품질 검토에서는 실패다.
- **구조상 원인:** 개인화 점수는 서버에서만 계산하고 모델의 후속 문맥에서 개인 스냅샷을 제거한다. 이유 생성에는 공개 작품과 당시 질문만 전달되므로 추천 당시 개인화 근거를 설명할 수 없다.
- **개선:** 추천 당시 처리 경로·근거를 소유권이 적용되는 서버 전용 메타데이터로 보관하고 후속 이유에 재사용한다. 개인 반응 전체를 모델에 전달할 필요는 없다. 당시 근거와 현재 취향을 구분한다.
- **수용 기준:** 개인화 이유가 이전의 서버 계산과 일치하고, 실제로 하지 않은 취향 분석이나 개인 기록을 만들지 않아야 한다.

### P1-4. 설명 가능한 취향 조건을 확인 불가로 일괄 거절함

- **재현:** “스포일러 없이 반전 있는 스릴러 영화 두 편만 한 줄씩 추천해줘”.
- **관찰:** 분류에서 `반전 있는`을 `UNVERIFIABLE`로 만들고 추천을 중단했다. 합성 카탈로그에는 `거듭되는 반전과 비밀을 마주한다`는 공개 줄거리 후보가 있었다.
- **영향:** 폭력 장면 부재 같은 보장 불가 조건과, 공개 줄거리 근거로 해석할 수 있는 선호 조건의 경계가 지나치게 보수적이다. 요청한 두 편을 못 채우더라도 근거 있는 한 편이나 구체적인 확인 질문을 제시할 여지가 있다.
- **개선:** 사실 필터·주관적 선호·보장 불가 조건·답변 작성 지시를 구분하고, “반전/몰입감/잔잔함/여운/전개 속도” 같은 선호를 근거에 따른 해석으로 처리한다. 조건을 조용히 버리지는 않는다.
- **수용 기준:** 근거가 있으면 그 범위에서 설명하고, 없으면 어떤 조건의 근거가 부족한지 명시한다. 반전 내용 자체를 노출해서 근거를 증명하지 않는다.

### P1-5. 실제 러닝타임 데이터 보강이 여전히 필요함 — 기존 미해결

합성 데이터에서는 2시간 미만/정확히 90분/20분 회당 조건과 미등록 값 제외가 맞았다. 그러나 현재 수집 스크립트의 시간 정보 보강과 실제 MySQL 값의 충실도는 이번에 검증하지 않았다. 필드·필터 구현만으로 실제 웹의 시간 추천이 유용해지는 것은 아니다. 믿을 수 있는 출처로 보강하고 영화/대표 회당 값의 등록률·오류율을 별도로 측정해야 한다. 이 항목은 이번에 실제 DB의 결측률을 새로 측정한 결과가 아니다.

### P2-1. 추천 편수는 맞아도 요청한 출력 길이를 따르지 않음

“스릴러 영화 두 편만 한 줄씩 추천해줘”는 두 편을 골랐지만 유형·공개일·장르·시간·인용·해석·전체 줄거리를 모두 출력했다. 원인은 서버의 고정 렌더링에도 있다. 편수와 응답 형식을 별도 검증된 값으로 관리하고, 간단한 추천은 제목+핵심 이유로 표시하며 상세를 후속 질문에서 제공하는 방식이 적절하다.

스포일러 제외 질문에서는 이번 줄거리에 범인·결말이 없어 노출을 관찰하지 않았다. 다만 서버가 저장 줄거리를 그대로 붙이는 구조여서 **스포일러 없는 응답을 보장했다고 평가할 수 없다.** 스포일러가 들어 있는 별도 카탈로그 사례가 필요하다.

### P2-2. 추천 이유가 장르 설명의 반복으로 끝남

스릴러 세 편의 후속 이유가 모두 `스릴러 장르가 표시되어 요청에 부합합니다`로 반복됐다. 잘못된 인용은 아니지만 작품 간 차이를 설명하지 못한다. 선택 근거가 제목이나 장르 한 단어뿐인 경우도 있었다. 장르 일치에 더해 추적 수사·고립 상황·단서와 반전 등 공개 줄거리의 구별되는 요소를 연결하는 평가 기준이 필요하다. 원문 인용 정확성과 설명의 설득력은 별개다.

### P2-3. 확인 질문·감사 응답이 상황을 설명하지 못함

“60분 이하이면서 2시간 넘는 영화”에 시간 충돌을 설명하지 않고 제목·ID·최대 두 요청이라는 공통 문구를 반환했다. “고마워”에도 다시 “안녕하세요!”와 기능 소개를 출력했다. 확인 불가·시간 충돌·모호한 작품·요청 개수 초과를 구분하는 짧은 안내와 감사 응답이 필요하다.

### P2-4. 조건 추출 완전성과 사용자 언어를 별도로 평가할 필요

“부모님이랑 주말 저녁에 편하게 볼 **영화**”는 결과가 모두 영화였지만, 분류 조건에는 상황/분위기만 있고 명시적 MOVIE 조건이 빠졌다. 결과가 우연히 맞는 경우도 있어 최종 작품만 검사하면 누락을 놓칠 수 있다. 영어 추천 질문에도 한국어 고정 렌더링을 반환했다. 한국어 전용 제품인지 사용자 언어에 맞출지 결정하고, 미지원 언어 정책도 정한다.

### P2-5. 지연·비용 최적화는 품질 수용과 함께 관리

서비스 중앙값 5.830초, p95 10.554초, 최대 18.576초였다. 긴 분류 지시·구조화 스키마·최근 대화 재전달의 비용을 측정하고, 기본 추천 편수/출력 길이를 줄이는 방식을 우선 검토한다. 스트리밍은 체감 대기 개선에 도움이 될 후보지만 이번 오류나 모순을 해결하는 기능은 아니므로 안정화보다 앞서 시작하지 않는다.

### P3 — 후속 확장

감독·배우·국가·언어·등급·완결 여부의 검증된 메타데이터, 유사 작품 탐색, 의미 검색, 장기 취향 기억, 실시간 시청 가능 서비스 연동을 별도 기능으로 검토한다. 현재 없는 정보를 모델 지식으로 카탈로그 사실처럼 보충해서는 안 된다. 벡터 DB 도입만으로 분류 잘림·원문 변조·개인화 이유 모순이 해결되지는 않는다.

## 4. 이번에 확인한 개선 효과

- 스릴러 여러 편 추천 후 단수 표현 “이 영화를 추천한 이유”는 전체 목록의 이유를 설명했다.
- 겨울 추천 → 이유 → 봄 배경으로 변경, 첫 번째 작품 줄거리, 감사 전의 더 이전 추천 참조가 맞았다.
- 시간·연도·장르 조건과 알 수 없는 시간의 제외, 조건 초기화가 대부분 정상 처리됐다.
- 이미 반응한 작품을 제외한 개인화, 공개 추천 반복 제외가 맞았다. 반복 제외 후 후보가 없을 때 기존 작품을 다시 채우지 않았다.
- 감독·연령 안전 보장·실시간 넷플릭스 정보는 확인한 척하지 않았다.
- “한 편만”은 한 편을 반환했고 오타와 영어 요청도 장르/시간 조건은 맞췄다.
