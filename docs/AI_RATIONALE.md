# 추천 이유 후속 질문 — 2026-11-18

최신 구현(2026-11-24): 새 단일 추천의 최초 요청과 당시 서버 개인화 근거를 저장하고 이유 답변에 이어 사용한다. 반응 변경과 반복 질문 뒤에도 당시 기준을 유지하며 모델에는 점수를 보내지 않는다. 기존 고정 실제 모델/H2 4턴에서 이전 두 미달 항목이 통과했다. [추천 출처 보존](AI_RECOMMENDATION_PROVENANCE_2026-11-24.md)을 참고한다. 아래 내용은 이전 경로/평가 기록이다.

2026-11-24 개인화 후속 수용 검사: 소유권·비공개 기록 제외·저장 계약은 통과했지만, 당시 서버 취향 근거와 반복 질문의 최초 요청 연결은 미달이다. 제품 변경 없이 고정 합성 H2 및 실제 모델4턴으로 확인했다. [검사 결과와 다음 구현](AI_PERSONALIZED_RATIONALE_2026-11-24.md)을 참고한다. 아래 설명은 기존 공개 카탈로그 근거 경로의 범위다.

후속 확장: 최초 추천의 조건 추출/제외/길이/배경/분위기를 공통 구조로 일반화했다. [AI_CONSTRAINTS.md](AI_CONSTRAINTS.md)를 참고한다. 아래 9/9는 앞선 이유 후속 기능의 당시 검증 기록이다.

사용자 웹 테스트에서 `겨울에 볼 만한 추천 영화` → 작품 추천 → `이 영화를 추천한 이유는 뭐야?`가 일반 설명(EXPLAIN)으로 분류되고, 현재 질문만 전달되어 앞 작품을 모른다고 답했다. 일반 추천 응답도 검증한 작품 정보만 출력하므로 선택 이유는 기록되어 있지 않았다.

최초 수정은 **앞 추천의 작품을 연결해 추천 근거를 설명하는 기능**이었다. 이후 사용자 요청으로 첫 일반 추천에도 검증한 근거와 모델의 해석을 함께 표시하고, 명시적 겨울 검색에 공개 계절 단서를 필수 조건으로 추가했다. 최신 범위와 실제 모델 3/3 검증은 [AI_RECOMMENDATION_QUALITY.md](AI_RECOMMENDATION_QUALITY.md)를 참고한다. Phase 7은 시작하지 않는다.

후속 재발 보고에서 `안녕?` → `스릴러 추천 해줘` → 세 작품(ID 99, 80, 93) → `이 영화를 추천한 이유는 뭐야?`가 확인 질문으로 끝났다. 기존 코드와 실제 모델 테스트가 다중 작품의 이런 표현을 모호함으로 취급했다. 이를 수정해 **일반적인 이유 후속 질문은 앞 목록 전체를 작품별로 설명**한다. 하나를 임의로 고르지 않으며 특정 순서/제목을 지정하면 그 작품만 설명한다. 상세 줄거리의 단일 대상 모호함은 별도 정책으로 유지한다.

## 동작

- 분류에 `RATIONALE`을 추가했다. “이 영화 추천한 이유”, “왜 이걸 골랐어?”, “두 번째는 왜 추천했어?”처럼 의미로 분류한다. 키워드 라우팅 fallback은 없다.
- 서버가 소유권을 확인하고 준비한 최근 대화의 기존 참조 메타데이터로 작품 ID를 해결한다. 1~6 assistant 턴, 위치 1~5 범위이며 **RATIONALE의 위치 0은 해당 턴 전체 목록(최대 5편)**이다. DETAIL의 위치 0은 기존처럼 단일 작품에만 쓸 수 있다. 텍스트의 ID·모델 기억을 근거로 쓰지 않는다. RATIONALE은 직접 title/contentId/year를 받지 않는다.
- 참조한 assistant 답변 바로 앞의 사용자 질문을 당시 요청으로 사용한다. 전체 이력·비공개 목록·취향 점수는 추가 생성 호출에 보내지 않는다. 추천 목록 뒤의 일반적인 “이 영화 추천 이유”는 목록 전체를 설명한다. 이전 질문/참조가 없거나 비공개 목록/메타데이터 없는 기록이면 확인 질문을 한다.
- 현재 Content를 조회하고 공개 CatalogCandidate(장르, 줄거리 최대 400자 등)와 당시 요청/현재 질문만 도구 없는 모델 호출에 전달한다. 여러 편도 **한 번의 일괄 생성**을 사용하며 전부 다시 읽어 변경/삭제 시 실패 처리한다. 첫 조회에서 누락된 작품이 있으면 새 추천을 요청하고 부분 목록을 조용히 설명하지 않는다.
- 단일 작품은 최대 두 개의 인용/400자 해석, 일괄 설명은 작품당 최대 한 개의 40자 인용/100자 해석을 strict JSON으로 받는다(프롬프트는 해석 70자 이하 권장). 모든 요청 ID가 정확히 한 번씩 반환되어야 하며 누락·중복·알 수 없는 ID·다른 작품의 근거 혼용은 실패한다. 서버가 필드 enum, 추가/중복/누락 필드, trailing JSON, 길이와 해당 작품 원문 포함 여부를 검증하고 원래 추천 순서대로 렌더링한다.
- 답변은 서버가 쓴 실제 제목/ID, **카탈로그에서 확인한 근거**, **요청과의 연결(모델의 해석)**을 구분한다. 근거가 없으면 해석을 출력하지 않고 부족함을 안내한다. 장르/줄거리가 아예 없으면 생성 호출도 하지 않는다.
- 계절·분위기·개인 취향 적합성을 보장하지 않는다는 안내를 덧붙인다. 모델에도 겨울/눈/크리스마스 등을 카탈로그 근거 없이 단정하거나 부실한 추천을 억지로 옹호하지 않도록 지시한다.

이것은 **현재 카탈로그와 참조한 요청을 대조한 설명**이며 처음 모델의 실제 선택 과정을 복구한 기록이 아니다. 인용의 원문 존재는 결정적으로 검증하지만 자유 텍스트 해석의 모든 의미·사실성은 검증할 수 없다. `catalogGrounded=true`는 실제 작품/근거 사용을 뜻하며 해석 전체의 진실 보증은 아니다. 계절/분위기 적합성에는 별도 평가가 필요하다. 특정 작품/조건 질문이 원래 추천 턴 밖으로 계속 이어질 때 초기 요청을 자동으로 추적·복원하는 새 저장 메타데이터는 추가하지 않았다.

기존 턴 예산(기본 20초, 출력 800토큰)을 분류/근거 생성/조회가 공유한다. 근거 후속은 정상적으로 분류 1 + 생성 1, 재시도 0이다. 복합 계획에서 RECOMMEND/PERSONALIZED/EXPLAIN/RATIONALE은 합계 최대 하나만 허용한다. 반응 목록을 포함한 복합 답변 전체는 후속 모델 문맥에서 제거하고 참조도 남기지 않는 기존 정책을 유지한다. 네트워크 호출은 DB 트랜잭션 밖에서 수행하고 오류 시 부분 턴을 저장하지 않는다. HTTP API/DB schema/configuration/frontend/dependencies는 바뀌지 않는다.

## 검증

오프라인 테스트는 원문 인용 위조·strict parsing·공통 사용량/예산·모호한/비공개/질문 없는 참조 차단·현재 DB 재확인·추천→이유 턴의 저장/복원·실패 시 원자성을 검사한다. 기존 v1 61-case corpus는 과거 측정 비교를 위해 바꾸지 않았으며 새로운 RATIONALE은 전용 테스트에서 검증한다. 기존 57/61 측정은 이전 분류기 결과로 남아 있고 새 분류기의 전체 v1 품질 점수는 재측정하지 않았다.

사용자의 앞선 실제 평가 승인 범위에서 다음 선택 실행도 수행했다.

```powershell
# 별도 비공개 CHAT_EVAL_OPENAI_API_KEY / CHAT_EVAL_MODEL 환경 설정 후 실행
.\mvnw.cmd test '-Dtest=RecommendationRationaleLiveTest' '-DchatRationaleLive=true'
```

최초 `gpt-6-luna` 7/7 측정은 다중 작품을 확인 질문으로 취급한 이전 정책의 결과다. 재발 수정 후 **9/9 통과**, 제공자 요청 15회. 인사→세 작품→동일한 이유 질문(ID/순서 포함), 목록 전체, 명시한 두 번째/더 이전 작품, 상세 질문의 모호함, 비공개 목록과 타인 조회를 검사했다. 정제 보고서: `target/chat-quality/rationale-20261118040117256670500.json`; 실행 로그: `target/rationale-group-live.log`. 합성 공개 카탈로그/대화만 사용했으며 실제 사용자 DB를 읽지 않았다. 이 평가는 실제 분류·원문 근거 형식·라우터 계약을 검증한다. 화면에서의 자연스러움이나 해석 문장 전체의 사실성을 채점하지는 않는다. 기본 Maven test에서는 네 유료 평가 클래스가 모두 skip되고 키도 읽지 않는다.

원문 인용과 해석을 분리하는 이유는 [OpenAI Docs의 Structured Outputs 오류 안내](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes)도 참고할 수 있다.

Eclipse 실행본 동기화 후 **F5 → 기존 백엔드 중지 → 재실행**한다. Eclipse 자체 재시작은 보통 필요 없다. `안녕?` → `스릴러 추천 해줘` → `이 영화를 추천한 이유는 뭐야?`로 세 작품의 이유가 한 답변에 각각 나오는지 확인한다. `두 번째는 왜 추천했어?`는 한 작품만 설명해야 한다. 새로고침 후 저장된 답변도 확인한다. 이전 메타데이터 없는 답변은 자동으로 추측하지 않으므로 새 추천에서 시작한다.
