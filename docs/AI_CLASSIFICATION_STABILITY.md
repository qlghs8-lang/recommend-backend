# 분류·복합 요청 안정화 — 2026-11-18

품질 개선 1단계. 감사 P1-1(분류 출력 잘림), P1-2(복합 요청 원문 변조)의 구조적 원인을 줄이는 변경이다. 실제 모델 품질 게이트 재통과를 의미하지 않는다.

## 변경

- `ClassifierPlan`은 제공자 전용 형식을 검증하고 기존 `ChatPlan`/`ChatIntent`로 변환한다. 공개 HTTP API와 저장 스키마는 바뀌지 않는다.
- 인사·일반 설명 등 유형이 필요 없는 분류는 `route`만, 목록은 `route/media`, 추천 이유는 `route/referenceTurn/referencePosition`만 생성한다. 후속 [유형 보존 변경](AI_COMPOUND_MEDIA_2026-11-18.md)부터 추천은 `route/media/mediaSource`를 필수로 생성한다. 상세 조회만 작품 위치 필드를 갖는다. 쓰지 않는 null 필드와 질문 전체 재출력을 줄였다.
- 독립된 두 작업은 `splitAfter` 경계 하나를 선택한다. 서버가 최신 사용자 원문에서 공백 또는 문장 구두점 뒤의 경계 후보를 만들고, 각 경계를 고유하게 가리키는 짧은 원문 문자열을 JSON Schema enum으로 제공한다. 이 문자열도 신뢰하지 않는 사용자 데이터로 취급한다.
- 서버가 선택된 경계에서 원문을 두 부분으로 자른다. 두 부분을 이어 붙이면 공백·연결어·구두점까지 원문과 동일하다. 모델이 질문을 재작성하거나 끝 마침표를 추가할 수 없다. 예: `내 찜 목록을 보여줘. 그리고 내 취향으로 새 영화 추천해줘`에서 `보여줘.`를 선택하면 두 번째 작업은 ` 그리고 내 취향으로 새 영화 추천해줘`다.
- 경계 문자열은 최대 100 UTF-16 문자, 후보는 최대 128개다. 고유 경계가 없거나 후보 한도를 넘는 긴 복합 문장은 모델에 단일 CLARIFY를 요청한다. 긴 단일 요청은 계속 지원한다. 단일 요청·비교는 경계가 null이어야 한다. 경계는 분할 위치만 지정하며 의미상 올바른 작업 선택을 보장하지 않는다.
- 분류 상한은 `min(1024, max(16, 남은 예산 - min(256, 남은 예산/3)))`이다. 전체 800토큰이면 544, 2,048토큰이면 1,024다. 후속 생성의 예산을 남기되 전체 토큰·시간 제한을 올리거나 자동 재시도를 추가하지 않는다. 작은 전체 예산으로 복잡한 조건을 항상 처리한다고 보장하지 않는다.
- `ChatRouter`의 원문 범위 검사, 요청 수/실행 경로 제한, 조건 검증, 참조 소유권 검사, 원자적 저장은 유지한다. 제공자 출력에서 기존 형식·추가 필드·없는 경계·중복 키를 거절한다. 기존 v1 정답 JSON과 과거 평가 결과는 변경하지 않는다.
- 유료 평가기 두 곳의 분류 상한 보고 값을 실제 배분 함수로 바꿨다. 과거 보고서의 512토큰 관측값은 그대로 보존한다.

[OpenAI 공식 구조화 출력 지침](https://developers.openai.com/api/docs/guides/structured-outputs)에 따라 중첩 anyOf의 각 객체는 필요한 필드를 모두 required로 선언하고 additionalProperties=false를 유지한다. 서버 파싱에서도 필드와 타입을 별도로 검증한다.
