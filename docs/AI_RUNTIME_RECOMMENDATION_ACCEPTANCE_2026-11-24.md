# 실제 시간 데이터의 추천 경로 수용

2026-11-24. **실제 카탈로그 기반 SQL·도구·JWT/HTTP·저장 계약 수용을 완료했고, 생성 중 변경된 시간값을 놓치는 오류를 수정했다.** AI 분류/선택은 고정 테스트 구현이다. 실제 모델의 자연어 해석,브라우저 화면,운영 사용자 트래픽을 검증한 결과는 아니다.

## 발견한 오류와 수정

기존 추천 서비스는 생성 후 `ContentRepository.findByIdIn`으로 작품을 다시 읽고 시간 조건을 검증했다. 그러나 HTTP 요청에서 OSIV가 활성화되면 이미 조회한 JPA 관리 객체를 다시 사용할 수 있다. 같은 객체를 돌려받는 조회가 DB의 현재 필드로 새로고침된다는 보장은 없다.

실제 MySQL/HTTP에서 이 문제를 재현했다. 합성 DB에 복사한 실제 작품53번(81분)을 후보로 읽고,AI 선택 도중 별도 JDBC 연결로121분으로 바꿨다. 요청은90분 이하 추천이었다.

| 검사 | 수정 전 진단 | 수정 후 작업본·실행본 |
|---|---:|---:|
| DB 현재 러닝타임 | 121분 | 121분 |
| HTTP 상태 | 200 | 502 AI_INVALID_RESPONSE |
| 응답에 오래된81분 표시 | 있음 | 없음 |
| 새 저장 메시지 수 | 2 | 0 |

신규 읽기 전용 `CatalogSnapshotRepository`는 공개 스칼라 필드로 `SELECT NEW Content(...)`를 실행한다. 생성자 결과를 기존 `CatalogCandidate.from`으로 정규화해 최종 조건/인용 검사에 사용한다. 관리 객체의 상태를 초기화하거나 다른 기능의 영속성 문맥을 비우지 않는다. 최종 후보는 기존과 같이 최대3개이며 쿼리 제한2초/쿼리 캐시 비사용을 명시했다. [Jakarta Persistence 3.2 §4.9.2](https://jakarta.ee/specifications/persistence/3.2/jakarta-persistence-spec-3.2#_constructor_expressions_in_the_select_clause)는 엔티티 생성자 결과가 키 유무에 따라 new/detached 상태임을 설명한다.

제품 수정은 신규 조회 인터페이스와 `CatalogRecommendations`의 조회 의존성 교체뿐이다. 공용 `ContentRepository`의 기존 동작과 실행본의 주석 차이는 그대로 보존했다. 기존 추천 단위 테스트와 실제 모델 테스트3개의 생성자/주입 타입만 새 인터페이스에 맞췄으며 질문·정답·평가기준은 바꾸지 않았다. API/프런트/DB 스키마·데이터/프롬프트/모델/한도는 변경하지 않았다. 이번 보장은 **최종 DB 조회 시점**의 재검증이며 이후 동시 변경까지 잠금으로 막는 구조는 아니다. 상세·추천 이유 등 다른 재조회 경로의 같은 위험은 별도 점검 범위다.

## 수용 환경과 결과

`RuntimeRecommendationAcceptanceTest`는 명시 opt-in이다. 실행본 설정은 내부에서만 사용하고 값/접속 오류/토큰을 보고서에 넣지 않는다. 실제 `myproject`의 공개 작품10필드와 시간 출처의 ID/필드/분/검토 해시만 읽기 전용으로 확인했다. 기존 회원·반응·대화는 조회하지 않았다.

실제468개와 출처21개(영화20/TV1)를 고유한 새 `recommend_runtime_acceptance_<랜덤>` 스키마에 복사했다. 같은 공개 ID/유형/시간·정렬 필드를 사용하고 합성 계정·JWT·방·대화만 이 DB에 썼다. Hibernate create는 이 새 스키마에만 적용한다. 원본 DB와 다른 이름/기존 비존재를 확인하고,임시 앱은 루프백 임의 포트에서 실행·종료했다. 생성 중 시간 변경도 복사본에서만 수행했다. 검사가 끝나면 생성한 스키마만 삭제하고 부재를 확인한다.

양쪽 모두 **수용 검사21개 통과**,HTTP 성공7턴/거절2턴이다.

| 범위 | 확인한 동작 |
|---|---|
| 실제 MySQL 검색8개 | 영화<=90/119/120/81/80분,TV회당<=25/24/26분. 공개 원본에 독립적으로 적용한 조건/정렬/12개 제한과 정확히 일치 |
| 미등록 제외 | 시간 조건의 모든 반환 ID가 출처 있는21개에 속함. 447개NULL은 시간 후보에 들지 않음 |
| 실제 도구 실행 | 매 생성에서 미등록 ID의 get_content 거절,그 제목을 검색해도 기존 시간 조건 유지,유효 후보 상세 읽기 확인. 사설 반응 도구는 사용하지 않음 |
| HTTP 조건 변경 | 두 시간 이내 영화2개→그중90분 이하→직전 목록의 최단 영화. 참조 범위와 새 시간 제한을 함께 적용 |
| 유형/시간 단위 전환 | 회당25분 이하 TV로 조건 교체. 영화 조건을 남기지 않고 유일한25분 TV를 반환,대표값/회차별 차이 표시 |
| 데이터 부족 | 회당24분 이하 결과 없음. 미등록 제외 안내/공개 참조 없음/선택 제공자 호출 없음 |
| 추정 금지 | 시리즈 전체 시간·모든 회차25분 보장 요청은 확인 불가 안내,작품 참조/선택 호출 없음 |
| 생성 후 검증2개 | 시간값81→121 변경과 미등록 ID 강제 선택을 각각502로 거절,양쪽 실패 턴 미저장 |
| 인증/보존 | 비로그인401,타인 방 GET/POST404,저장 응답 재조회 동일. 원본 공개 스냅샷·실제21개 시간·모든 출처/적용 시각 보존 |

81/80은 이 데이터의 실제 영화 최소값을 기준으로 정한 경계다. 원본 공개 스냅샷 지문은 양쪽 모두 `5f5559a3eea157209d4e114198086ac6e4233a6d146b5c2628421a845c7e4f27`이다. 실제 데이터는 기존468개/영화20개·TV1개 유효/나머지447개NULL 그대로다. TMDB·실제 모델 호출0회. 모델 토큰/평가 모델 환경변수는 현재 프로세스에 설정되지 않았으며 저장된 비밀을 검색하지 않았다.

## 실행한 검증

작업본 고정 수용/단위 테스트:

```powershell
.\mvnw.cmd -o -Dtest=RuntimeRecommendationAcceptanceTest,CatalogRecommendationsTest -DchatRuntimeAcceptance=true test
```

JUnit21개(새 수용1개+기존 단위20개) 통과. 새 수용 메서드 내부 검사21개는 별도 검사 수이며 JUnit21개와 더해 집계하지 않는다. 최초 실제 수용은16개 검사 이후 시간 변경 거절에서 실패했고,제한된 진단을 추가한 재현도 실패했다. 두 실패 보고서를 보존했다. 수정 초기에는 생성자 타입을 쓰는 기존 실제 모델 테스트3개의 컴파일 의존성 오류가 있었고 주입 타입만 맞춰 해결했다. 정답을 완화하지 않았다.

- 작업본 전체 `.\mvnw.cmd -o test`: **521개 발견/463통과/58조건부 건너뜀/실패·오류0,BUILD SUCCESS**. 이 실행에서는 새 opt-in 수용도 건너뛰며 위 별도 실행에서 통과했다.
- Eclipse `.\mvnw.cmd -o -Dtest=com.example.recommend.chat.**.*Test -DchatRuntimeAcceptance=true test`: **426개/404통과/22조건부 건너뜀/실패·오류0,BUILD SUCCESS**. 새 MySQL/HTTP 수용도 이 실행에 포함된다.
- 실제 앱의 시간·출처 상태를 이전 적용 직후 전체 좁은 스냅샷과 비교해 동일함을 확인했다. 모든 소유 수용 스키마 잔여0이다. 기존 평가JSON13개/수집·적용Python13개를 보존했다. 실제 모델/브라우저/프런트 테스트는 이번에 실행하지 않았다.

근거는 작업본 `target/runtime-recommendation-acceptance`의 `mysql-http-initial-failed.log`, `mysql-http-diagnostic.log`, `compile-initial-failed.log`, `mysql-http-fixed.log`, `full-offline.log`, `report-*.json`, `verification.json`, 동기화/보존 매니페스트다. 실행본에는 같은 target 폴더의 `chat-verification.log`, `report-20261124100439276783800.json`이 있다. 작업본 수정 전 진단은 `report-20261124095957514830300.json`,수정 후는 `report-20261124100251637753500.json`이다.

## 동기화와 다음 단일 기능

Eclipse에 새 제품1개/기존 제품1개/새 수용1개/기존 테스트4개/문서6개 총13파일만 동기화했다. 기존 제품1개·테스트4개·문서5개는 실행본 `target/runtime-recommendation-acceptance-sync-20261124`에 백업하고 원본/복사본 해시를 검증했다. 실행본 회귀/실제 수용 통과. 공용 저장소의 기존 주석 차이,로컬 설정,무관한 변경은 보존했다.

**Java 코드가 바뀌었으므로 Eclipse F5 후 백엔드를 중지하고 다시 실행해야 사용자 앱에 반영된다.** Eclipse 자체나 프런트를 재시작할 필요는 없다. 이 작업에서 시작/종료한 것은 임시 검사 앱이며 사용자 앱을 직접 재시작하지 않았다.

다음 단일 기능은 **실제 모델의 시간 조건 해석·후속 대화 수용**이다. 현재 공개 시간값을 사용하되 합성 계정/대화만 대상으로90분·2시간 미만·회당 길이·조건 변경·전체 시리즈 시간 거절을 고정된 작은 질문 묶음으로 검증한다. 평가용 키/모델을 개인 프로세스 환경에 설정하고 요청/시간/토큰 예산을 제한해야 한다. 이번 고정 분류 통과를 실제 의미 해석 정확도나 전체 품질 점수로 합산하지 않는다. 간헐503,다른 재조회 경로,TV 빈 배열/전체 보강/TMDB B~D/Phase7은 별도다.
