## 1. 수집할 수 있는 정보

작품별로 등록되지 않은 정보가 있을 수 있다. 영화와 TV는 필드명과 조회 API가 일부 다르다.

| 분류 | 정보 / 대표 필드 | 챗봇 활용 |
|---|---|---|
| 식별 | TMDB ID + 영화/TV 구분 | 작품 매핑, 중복 방지, 정보 갱신 |
| 제목 | `title` / `name`, 원제, 다른 제목 | 한국 제목·원제·별칭으로 검색 |
| 내용 | `overview`, `tagline` | 줄거리 설명, 추천 근거 |
| 장르 | `genres` | 장르 포함·제외 조건 |
| 날짜 | `release_date` / `first_air_date`, 국가별 공개일 | 연도 조건, 한국 개봉일 안내 |
| 길이 | 영화 `runtime`, TV `episode_run_time`, 회차별 `runtime` | 영화·회차 시간 조건 |
| 국가·언어 | 제작 국가, 원어, 사용 언어 | 국가·언어 조건 |
| 평가 | `vote_average`, `vote_count` | 평점과 평가 수를 함께 고려 |
| 인기도 | `popularity` | 인기 후보 정렬 |
| 인물 | 출연진 ID·이름·배역, 제작진 ID·이름·직무 | 배우·감독·작가 관련 검색 |
| 소재 | `keywords` | 시간여행·복수·우주 등 소재 검색 |
| 시청 등급 | 국가별 영화 등급 / TV 등급 | 한국 등급 기준 안내 |
| 시청 장소 | 국가별 구독·대여·구매 제공사 | 한국 OTT 제공 여부 안내 |
| TV 구성 | 시즌 수·에피소드 수·방영 상태·회차 정보 | 완결 여부, 분량, 회차 설명 |
| 작품 관계 | 영화 컬렉션, 추천·유사 작품 | 같은 시리즈·비슷한 작품 탐색 |
| 부가 자료 | 포스터·배경·예고편·리뷰·제작사·제작비·흥행 수익·외부 ID | 추천 카드, 부가 질문, 외부 데이터 연결 |

기본 상세 조회만으로 모든 정보를 얻을 수 있는 것은 아니다. 출연진·제작진, 키워드, 등급, OTT, 시즌 상세 등은 추가 조회가 필요하다. 지원되는 하위 조회는 `append_to_response`로 묶을 수 있다.

## 2. 대화 품질 개선을 위한 수집 우선순위

| 순위 | 보강 항목 | 기대 효과 |
|---|---|---|
| 1 | 영화·회차 러닝타임 실제 값 | 현재 시간 조건 검색에 필요한 데이터 확보 |
| 2 | 키워드·주요 출연진·감독 | 구체적인 소재 추천과 인물 관련 후속 대화 |
| 3 | 국가·원어·시즌 수·에피소드 수·방영 상태 | 조건 검색과 작품 설명 확대 |
| 4 | 한국 시청 등급·한국 OTT 제공 정보 | 관람 조건과 시청 장소 안내 |
| 5 | 시리즈 관계·추천·유사 작품 | 관련 작품 후보 확장 |

수집한 정보를 DB에 넣는 것과 AI가 활용하는 것은 별도 작업이다. 검색 조건, 서버 검증, AI 전달 데이터까지 연결해야 답변이 달라진다.

## 4. 데이터 해석과 저장 시 주의점

- **누락:** 미등록 값은 알 수 없음으로 처리하고, AI가 추정한 값을 사실 필드에 저장하지 않는다.
- **평점:** TMDB 평점과 IMDb 평점은 다르다. 평점 출처와 평가 수를 함께 보존한다.
- **인기도:** `popularity`는 실제 시청 횟수가 아니다.
- **TV 길이:** `episode_run_time`은 모든 회차의 동일한 길이를 보장하지 않는다. 정확한 전체 분량은 회차별 값이 충분할 때 계산한다.
- **TV 상태:** 방영 종료와 제작 취소를 구분한다. 방영 종료만으로 이야기의 완결성을 보장하지 않는다.
- **국가·언어:** 원어·제작 국가와 이야기의 배경 국가는 다르다. 한국어 요청도 모든 항목의 번역을 보장하지 않는다.
- **등급:** 한국 `KR` 등급을 구분해 저장한다. 등급만으로 특정 자극적 장면의 부재를 보장하지 않는다.
- **OTT:** 국가·이용 형태·확인 시점을 보존하고 갱신한다. 방송사 정보는 현재 OTT 제공 정보와 다르다. JustWatch 출처 표시가 필요하며 직접 재생 링크는 보장되지 않는다.
- **주관적 조건:** 힐링·겨울 감성·잔인하지 않음·해피엔딩 등이 일관된 전용 필드로 제공되는 것은 아니다. 공개 근거와 모델의 해석을 구분한다.
- **키워드·리뷰:** 태그 부재는 해당 요소의 부재를 뜻하지 않는다. 리뷰는 이용자 의견이며 키워드·줄거리·리뷰에 스포일러가 포함될 수 있다.
- **관련 작품:** TMDB 추천 결과도 내부 DB의 실제 작품과 매핑·검증한 뒤 안내한다.

저장 확장 시에는 출처·외부 ID·수집 시점·언어·국가를 함께 보존하는 것을 권장한다. 인물·키워드·OTT처럼 여러 값이 연결되는 정보는 별도 관계 테이블을 검토한다. 이는 설계 제안이며 아직 구현한 구조는 아니다.

## 5. 권장 활용 흐름

`TMDB 수집 → 우리 DB 저장 → 서버에서 조건에 맞는 작품 검색 → 필요한 근거만 AI에 전달 → 작품 ID와 조건을 검증해 답변`

이 방식은 검색으로 확보한 실제 데이터를 답변 근거로 제공하는 RAG다. 모든 작품 정보를 매번 프롬프트에 넣기보다, 질문에 필요한 후보와 필드만 전달한다.

## 6. 품질 개선 단계에 연결한 DB 확장 검토 — 2026-11-18

이번에는 DB 변경이나 외부 수집을 실행하지 않았다. 아래는 현재 `Content`, `CatalogCandidate`, `scripts/catalog_pool.py`를 다시 확인한 뒤 정리한 후속 설계이며, 제안한 관계 테이블은 아직 존재한다고 가정하지 않는다.

| 단계 | 기존 DB에 적용할 방향 | 완료를 판단할 검사 |
|---|---|---|
| A. 기존 시간 데이터 보강 | `contents.runtime_minutes`, `episode_runtime_minutes`를 재사용한다. 수집기가 생성하는 `catalog_import_sources`의 영화/TV+TMDB ID 매핑을 먼저 확인하고, 매핑이 검증된 작품만 상세 조회한다. 누락·0은 null로 유지하고 검증된 기존 값을 무조건 덮어쓰지 않는다. | DB 변경 전 읽기 전용 등록률 조사, dry-run 변경 내역, 잘못된 유형/ID 거절, 영화/TV별 등록률·유효 범위, 재실행 멱등성, 변경 전후 조건 추천 검사 |

현재 매핑의 `fetched_at`은 수집기에서 최초 삽입할 때 기록된다. 이를 모든 확장 필드가 갱신됐다는 의미로 재사용하지 않고, 보강 데이터의 제공자·수집 작업/시점·언어·국가(해당 시)를 따로 기록할 설계가 필요하다. 원제/별칭 검색과 평점 출처도 별도 후속 범위로 둔다.

메타데이터가 추가돼도 분류·서버 필터·검증·설명 경로에 연결되기 전에는 해당 조건을 지원한다고 안내하지 않는다. 초기 단계는 마이그레이션을 한꺼번에 늘리기보다 **A만 독립적으로 구현**하는 것이 적절하다. 11월18일 제안 시 미확인이었던 로컬 MySQL 매핑/시간 등록률은 아래 후속 조사에서 확인했다.

### A 후속 조사 — 2026-11-24

읽기 전용 조사 도구/테스트를 추가했다. 기존468개(영화230/TV238)와 정상 TMDB 매핑468개를 확인했고 두 시간 컬럼의 대상 값은 전부 NULL이었다. 중복/고아/유형 불일치/비정상 시간값0,두 테이블 InnoDB. 카탈로그 수를 유지하고 ID 추정 없이 상세 조회할 후보468개를 확정했다. 독립 스냅샷2회와 Eclipse 실행본의 해시 일치,작업본 새 테스트22개/기존 수집기19개/실행본 새 테스트22개 통과. API 수집/DDL/DB 보강은 하지 않았다.

후속으로 영화20/TV20개부터 상세 조회하는 **미반영 변경안(dry-run) 도구**를 구현했다. 기존 값 보호,TV 단일 대표값 정책,원본 필드/수집 시점,요청/시간/응답 크기 제한,현재 DB 재검증/부분 실패 차단을 포함한다. 도구 구현 당시 작업본·실행본 각각 신규28+기존 감사22=50개 테스트 통과. 초기 토큰 미설정 중단 후 사용자가 개인 터미널에서40회 수집을 완료했다. **영화20개(81~142분)·TV1개(대표 회당25분),총21개 변경안**,TV19개는빈 episode_run_time으로 건너뜀. 작업본/실행본의 현재 DB 재검증 결과가 원본 변경안과 전체 JSON 기준 동일하다. dry-run 재검토 당시 추가API0/DB쓰기0,기존468개와시간 등록률0%를 유지했다. 이후21개 적용·출처 보존을 아래 후속 단계에서 완료했으며 다음은 조건 추천 수용이다. TV빈 배열의 추가 조회는 별도 검토한다. [시간 등록률 조사](AI_RUNTIME_COVERAGE_2026-11-24.md),[실수집 검토·안전한 실행법](AI_RUNTIME_DRY_RUN_2026-11-24.md)을 참조한다.
