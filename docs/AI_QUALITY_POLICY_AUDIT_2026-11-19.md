## 1. 짧게 볼 만한 시리즈 있을까?

| 경로 | 실제 서비스에서 확인한 결과 |
| --- | --- |
| 기록된 CLARIFY | 모델 선택 호출/작품 참조 없이 “대상의 정확한 제목·카탈로그 ID 또는 최근 답변의 작품 순서”를 요구한다. 회당/전체 길이를 묻지 않는다. |
| 원본 RECOMMEND/ANY, 조건 없음 | 기존 검색기의 원문 유형 추론으로 영화는 제외된다. 다만 시간 조건이 없어서 대표 회당90분·10분·길이 미등록 TV가 모두 선택 후보에 들어온다. 합법 후보인90분 작품을 고정 선택하면 그대로 저장·출력된다. |

**판정:** “짧게”는 회당/전체/가벼운 감상의 의미가 모호하다. 현재 지시는 모호한 시간단위에 CLARIFY를 허용하므로 이를 불필요한 질문이라고 확정할 수 없다. 반면 실제 확인 문구가 누락된 시간단위를 묻지 않는 문제는 확인했다. 원본 계획을 무조건 강제해도 길이 조건을 만족하는 추천이 보장되지 않는다.

위 RECOMMEND 결과는 조건 없는 **원본 기대 계획**을 주입한 반례다. 원본을 통과했던 모든 실제 모델 응답도 조건이 없었다는 뜻은 아니다. 기존 실제 모델 진단의20분 추천 성공 기록도 취소하지 않는다. 이번에는 유효한 숫자 제한을 임의로 발명하지 않았다.

## 2. 없는 작품 XYZ의 줄거리 알려줘

원본 기대 제목은 `없는 작품 XYZ`, 기록된 모델 제목은 `XYZ`다. 두 문자열 모두 사용자 원문에 포함되므로 기존 부분 문자열 검증을 통과한다. 상세 검색은 추출된 제목의 정확한 일치만 사용한다.

| H2 카탈로그 상태 | 기록된 XYZ 계획 | 원본 없는 작품 XYZ 계획 |
| --- | --- | --- |
| 두 제목 모두 없음 | 미발견 안내, 참조 없음 | 같은 미발견 안내, 참조 없음 |
| XYZ만 있음 | XYZ 상세·참조 저장 | 미발견 안내 |
| 없는 작품 XYZ만 있음 | 미발견 안내 | 해당 작품 상세·참조 저장 |
| 두 제목 모두 있음 | XYZ 상세·참조 저장 | 없는 작품 XYZ 상세·참조 저장 |

**판정:** 빈 카탈로그에서 응답이 같다는 이유로 무해한 대안 추출로 확정할 수 없다. 제목 충돌 시 실제 작품과 후속 공개 참조까지 달라진다. 동시에 “없는 작품”이 제목의 일부인지 설명 표현인지 이 문장만으로 확정하기 어렵다. 실제 사용자에게 잘못된 줄거리가 제공됐다는 증거도 아니다.

후속 평가에서는 미등록 작품의 제목을 명시적으로 인용하거나 ID로 지정하는 사례와, 인용되지 않은 모호한 제목 경계 사례를 분리해야 한다. 기존 v1을 이런 새 문장으로 덮어쓰지 않는다. 임의의 최장 부분 문자열 선택이나 DB에 있다는 이유만으로 짧은 제목을 채택하는 규칙도 추가하지 않았다.

## 3. 달빛 항해와 숲의 기록 중 더 뛰어난 연출의 작품은 뭐야?

| 경로 | 실제 서비스에서 확인한 결과 |
| --- | --- |
| 기록된 UNSUPPORTED | 기능 목록과 “실시간 뉴스·순위·시청 가능 서비스 조회” 미지원 안내. 우열 답변/카탈로그 참조/추가 모델 호출 없음. |
| 원본 CLARIFY | 이미 제목 두 개를 준 질문에 제목·ID를 다시 요구. 우열 답변/카탈로그 참조/추가 모델 호출 없음. |

**판정:** 두 경로 모두 근거 없는 우열을 만들지 않는 기능 경계는 지킨다. 하지만 “뛰어난 연출”은 실시간 순위 요청과 같지 않고, 이미 지정한 제목을 다시 받는 것도 질문을 해결하지 못한다. UNSUPPORTED를 자동 성공 처리하거나 CLARIFY만 강제하는 방식으로 해결할 문제가 아니다.

현재 제품의 두 작품 비교는 저장된 유형·공개일·장르·줄거리의 병렬 안내이며 연출 해석이나 우열 판정은 제공하지 않는다. 이후 이 한계를 직접 설명하고 저장된 정보 비교를 제안하는 경로를 별도로 검증해야 한다. 배우/감독 메타데이터 확장만으로 주관적 우열의 근거가 생기는 것은 아니다.

## 다음 단일 기능

**시간 단위가 모호한 추천에 맞는 확인 질문**을 먼저 구현한다. 근거는 첫 사례와 기존 감사 P2-3이다. 분류 결과에 서버가 검증할 수 있는 제한된 이유를 전달하고 고정 문구로 질문하는 방식을 검토한다. 사용자 원문을 근거로 구분하고 추가 자유 생성 호출이나 숫자 추정을 사용하지 않는다.

수용 예시:

1. “짧게 볼 만한 시리즈”에는 회당 길이인지 전체 시청 시간인지 묻고 제목·ID를 불필요하게 요구하지 않는다.
2. 회당 길이를 명시하면 기존 TV 대표 회당 길이 정책을 적용한다. 전체 길이는 확인 가능한 것으로 바꾸어 말하지 않는다.
3. 제목/참조 모호성·요청 수 초과 등 기존 다른 확인 경로와 strict 검증·권한·저장·비용 상한을 보존한다.
4. 새로운 시간단위 정책의 평가는 별도로 기록한다. 원본 v1과 과거58/61을 유지하고 실제 모델 재측정과 H2 재생을 구분한다.

제목 경계, 우열 안내, TMDB 확장, Phase7은 이번 작업에서 구현하지 않는다. 간헐503은 안전한 `AI_PROVIDER_FAILURE` 이벤트가 오면 해당 사고를 우선 조사한다.
