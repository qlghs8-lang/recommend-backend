## 최초 추천 이유

일반 추천은 기존 도구 선택 호출에서 ID와 이유를 함께 받는다. 별도의 작품별/이유 생성 호출을 추가하지 않는다. strict JSON `recommendations`는 최대 3편이며 각각 `contentId`, `evidence`, `interpretation`만 가진다. 작품당 TITLE/GENRES/OVERVIEW의 정확한 연속 인용 최대 1개·40 UTF-16 단위, 해석 최대 100단위(프롬프트 70 이하 권장)다. 서버는 알려진 ID·중복·필드·길이·자기 작품의 인용을 검사하고, 생성 후 다시 읽은 실제 Content에 대해서도 검증한다. 삭제·원문 변경·누락 이유는 실패하며 부분 턴을 저장하지 않는다.

출력은 실제 제목/ID, `카탈로그 근거: …`, `추천 이유(모델의 해석): …`, 기존 줄거리 순서다. 근거 없는 항목에는 모델 해석 대신 근거 부족을 안내한다. 인용 존재는 검증하지만 해석의 모든 의미·자연스러움·취향 적합성을 보장하지는 않는다. `catalogGrounded` 역시 전체 해석의 진실 보증은 아니다.

명시적 개인화는 기존 서버 장르 점수/이유를 유지한다. 모델에 개인 취향을 새로 전달하지 않는다. 반응 표시 요청 또는 해당 턴의 반응 도구 조회가 있으면 자유 텍스트 해석은 출력하지 않고 공개 인용과 기존 서버 반응 요약만 사용해 비공개 정보가 일반 이력으로 재전송되는 것을 막는다. 기존 추천 이유 후속 기능은 [AI_RATIONALE.md](AI_RATIONALE.md)를 참고한다.

## 겨울 검색

검색의 불필요한 요청어 `보면`, `좋을`, `소개` 등을 제거한다. 인식한 명시적 겨울 요청은 **겨울 관련 공개 단서**를 필수 AND 조건으로 추가한다. 제목 또는 모델에게 보이는 줄거리 첫 400자 안에서 겨울·크리스마스·설경·눈보라·눈 덮/쌓/내리 등과 제한된 영어 표현을 찾는다. 일반적인 `눈앞`, `눈물`이나 단순한 편안함은 겨울 단서가 아니다. 기존 장르/제목 검색 및 영화/시리즈 필터는 이 조건 안에서 적용된다.

`다른거 추천`, `다른 영화 추천`처럼 내용이 생략된 후속은 최근 사용자 조건을 재사용하고 명시된 새 매체 유형은 우선한다. 검색/상세 도구에서도 겨울 조건을 유지하며, 도구가 반환한 부적합 후보와 생성 후 계절 단서가 사라진 작품은 허용하지 않는다. 적합 후보가 없으면 무관한 인기 작품으로 채우지 않고 결과 없음과 분위기 조건 대안을 안내한다. 모호한 겨울 제외 표현은 확인 질문으로 처리한다.

이는 제한된 어휘 규칙이며 모든 계절/분위기의 의미 검색은 아니다. `겨울에`, `겨울엔`, `겨울철`, `winter` 등 인식 문법·공개 메타데이터의 충실도에 의존한다. 제목에 겨울 단서가 있어도 작품 전체의 계절감이 보장되지는 않는다. 임의의 부정/복합 문법, 긴 후속 사슬의 최초 조건 복원, 여름/가을/봄/일반 분위기는 이번 범위 밖이다. 실제 DB에 단서가 부족하면 적은 추천 또는 결과 없음이 정상이다.

## 검증 및 실행

오프라인 테스트는 계절 단서와 잡음어 구분, 400자 경계, 매체/장르 필터, 후속 조건, 도구 우회 차단, 첫 이유의 저장/참조, 원문 변경·위조·누락 거절, 반응 정보 노출 억제, 기존 공유 예산/도구 루프를 검사한다. HTTP/DB schema/configuration/dependencies/frontend는 바꾸지 않았다. 기본 20초/출력 800토큰 예산과 최대 3회 도구·4회 선택 제공자 요청을 유지한다. 이유가 길어져 출력 토큰 사용량은 늘 수 있다.

실제 모델 평가는 별도 비공개 환경 설정 후 명시적으로 실행한다. 기본 테스트에서는 키를 읽거나 유료 호출을 하지 않는다.

```powershell
.\mvnw.cmd test '-Dtest=RecommendationQualityLiveTest' '-DchatRecommendationLive=true'
```

이번 승인된 실행은 gpt-6-luna **3/3 사례 통과**, 제공자 요청 5회, 입력/출력 6,834/768토큰이었다. 격리된 H2 합성 공개 카탈로그와 실제 분류/검색/선택/원문 검증을 사용했다. 첫 스릴러 이유(3편), 보고된 겨울 소개 문장(3편), 겨울·스릴러 교집합 없음(추가 추천 생성 0회)을 확인했다. 각 일반 추천은 분류+추천 2회, 빈 검색은 분류만 1회였으며 재시도는 없다. 정제 보고서 `target/chat-quality/recommendations-20261118043551178153100.json`, 로그 `target/winter-reasons-live.log`. 보고서에는 질문/응답 본문·키·개인 기록을 저장하지 않는다. 실제 사용자 DB/브라우저 검증과 해석 문장 전체의 사실성/자연스러움 채점은 수행하지 않았다. 기존 전체 61-case 분류 품질 점수 57/61은 이전 분류기의 역사적 결과이며 재측정하지 않았다.

Eclipse 실행본 동기화 후 F5 → 백엔드 중지 → 재실행한다. 새 대화에서 `안녕` → `겨울에 보면 좋을 작품 소개 해줘`로 겨울 근거와 첫 추천 이유를 확인하고, 이어 `저 작품들을 추천한 이유는 뭐야?`와 `두 번째는?`를 확인한다. `스릴러 추천 해줘`에도 첫 답변의 작품별 이유가 있어야 한다. 실제 카탈로그에 겨울 근거가 없으면 결과 없음이 예상 동작이다. 새로고침 후 이유와 후속 참조가 유지되는지도 확인한다.
